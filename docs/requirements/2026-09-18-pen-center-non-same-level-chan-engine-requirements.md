# chant_agent 缠论结构引擎需求规格：笔中枢与非同级别分解

## 1. 文档定位

本文档定义 `chant_agent` 下一版中枢、走势类型、级别递归与买卖点引擎的正式需求。

理论语义以 `../读缠论108课札记.pdf` 为主要依据，重点参考第 17、18、20、21、29、33、35、38、39 课。工程采用一个明确的简化前提：在每个行情周期图内部，把该周期的确认笔视为最低一级已完成走势单位，从笔开始递归；不使用不完整的分钟数据伪造日线以下真实级别。

本模型称为“周期内笔递归模型”。其中 `L1/L2/L3...` 仅表示当前行情周期数据域内部的结构级别。例如日线图上的 `L2` 不是周线中枢，也不等于原文中由真实低周期逐级递归得到的某个固定时间级别。

本文档是需求与设计基线，不代表当前代码已经满足这些规则。

## 2. 重构目标

结构计算链路统一为：

```text
当前周期 K 线
→ 当前周期确认笔
→ 非同级别走势工作区
→ 进入段 + 最早合法三笔核心
→ L1 笔中枢
→ 延伸 / 离开 / 回试 / 新生 / 扩张
→ 结构背驰与一、二、三类买卖点
→ 确定走势边界与盘整、上涨、下跌
→ 由已完成低级走势递归出 L2/L3...
```

重构必须解决以下现有问题：

1. 禁止对全部笔做三笔滑动窗口并把每个重叠窗口都画成正式中枢。
2. 禁止把同一批笔反复归属给多个并列中枢。
3. 禁止用 `A` 与 `B` 重叠、`B` 与 `C` 重叠，推导 `A/B/C` 全部属于一个巨型中枢。
4. 禁止把笔直接重复用作所有高级别中枢的构成单位。
5. 禁止仅按三笔、九笔或固定数量自动结束走势、升级中枢。
6. 禁止仅凭反向中枢、MACD、幅度或斜率中的任一单项机械切分走势。
7. 中枢、买卖点和走势必须由同一个按时间推进的结构状态机联合确定，不能先全局生成中枢，再事后任意切走势。

## 3. 原文规则与工程简化边界

### 3.1 保留的原文核心语义

- 中枢由至少三个连续、已完成的低级走势类型重叠形成。
- 初始中枢核心由最初三个低级走势单位确定：
  - `ZD = max(low1, low2, low3)`
  - `ZG = min(high1, high2, high3)`
  - 只有 `ZD < ZG` 才存在严格价格重叠；单点接触不成枢。
- 一个完成走势只包含一个同级中枢时，为盘整。
- 一个完成走势至少包含两个依次同向、彼此不重叠的同级中枢时，为趋势；向上排列为上涨，向下排列为下跌。
- 中枢延伸、新生、扩张必须区分。
- 第三类买卖点要求完整低级走势离开中枢，随后第一次完整低级走势回试不重新进入中枢。
- 趋势完成由第一类买卖点解决；第三类买卖点首先解决的是中枢破坏与离开有效性，不等价于任意走势自动结束。
- 非同级别分解允许 `a + A + b` 中的 `a/b` 低于 `A` 的级别，且可以是一笔或一个内部无中枢的多笔走势段。

### 3.2 工程明确采用的简化

- 当前周期确认笔视为最低级已完成走势单位。
- L1 中枢的核心由三笔构成。
- 当前周期内部递归生成 L2/L3；不把它们映射为真实 30 分钟、周线或月线级别。
- 原文中的“力度”不是一个单一数值。工程必须保存结构证据，并可使用 MACD、价格幅度、时间跨度等作为辅助诊断；任何辅助指标都不能单独定义背驰。
- 对无法由当前周期数据唯一判定的结构，输出 `candidate`、`provisional` 或 `undetermined`，不得通过默认值强行确认。

### 3.3 本项目的唯一分解约定

原文的中枢定义本身只要求三个连续低级走势重叠；本项目为了避免全局三笔滑窗产生大量无意义中枢，增加以下正式分解约定：

```text
走势边界
→ 进入段 entry component
→ 三笔核心 core
→ 延伸 / 离开 / 回试
```

进入段不属于中枢核心，但属于中枢的结构上下文。正式中枢必须能够在一个走势工作区中找到明确的进入段；仅在数据左边界出现、没有进入上下文的三笔重叠，只能记为边界候选，默认不显示为正式中枢。

## 4. 基础对象定义

### 4.1 笔 `PenUnit`

- 使用当前工程已经确认的标准笔算法，本次不重写笔识别规则。
- 只有已完成、方向明确、端点真实、处于同一连续行情区间的笔可参与正式结构。
- 相邻笔必须方向交替并共享一个真实端点。
- 缺口、数据断点、序列切换不能由结构算法跨越。

### 4.2 无中枢走势段 `CenterFreeComponent`

一个进入、连接、离开或回试段可以由一笔或多笔构成，要求：

- 源笔连续、不重复、方向交替。
- 内部不存在可在当前工作区内提交的同级正式中枢。
- 整体方向由首尾端点确定。
- 可以是 1、3、5、7 等多笔结构，但不能仅凭奇数数量判定级别。
- 组件价格范围取全部源笔的真实包络，而不是首尾连线。

### 4.3 中枢 `CenterFamily / CenterRevision`

逻辑上，一个中枢在延伸、扩张和级别升级过程中保持稳定的 `center_family_id`；数据库中每次结构变化保存不可变的 `CenterRevision`。

- 前端默认只显示当前有效修订，避免同一区域叠画 L1、L2、L3 多个矩形。
- 旧修订作为证据保留，可在诊断模式查看。
- “级别升级”在业务语义上是同一个活动结构的级别和范围变化；在持久化上必须新增修订，不能原地篡改历史证据。
- 升级不能靠重叠关系的传递闭包实现，必须有本级完整结构证据。

### 4.4 走势 `MovementFamily / MovementRevision`

- 走势与中枢联合构造，不允许先独立生成全部中枢，再把它们任意分组。
- 一个活动走势在其核心中枢升级后，可以同步升级级别；逻辑身份保持不变，保存新的走势修订。
- 已经确认完成的低级走势仍作为高级递归证据保留，不被删除。
- 当前有效视图只显示所选层级和分解视角，避免把父子走势同时画成互相竞争的正式走势。

### 4.5 结构点 `StructuralPoint`

统一承载：

- 趋势一买 / 一卖；
- 二买 / 二卖；
- 三买 / 三卖；
- 盘整背驰买点 / 卖点；
- 仅供分解使用的候选转折点。

每个点必须分别保存：

```text
point_date / point_price       真实转折端点
confirmed_at                   后续证据齐备时间
status                         candidate / confirmed / invalidated
point_type
level
source_unit_id
source_component_ids
center_family_id
center_revision_id
movement_family_id
evidence
invalidated_reason
```

`point_date` 不得被后续确认时间替代；`confirmed_at` 不得回填为历史点位日期。

## 5. L1 笔中枢构造规则

### 5.1 走势工作区优先

扫描从一个已确认或候选走势边界开始。状态机维护一个活动走势工作区，而不是在全量笔上滑窗。

在工作区内，从左到右寻找“最早合法三笔核心”：

1. 核心前三笔之前的全部连续笔构成进入段。
2. 进入段必须非空、内部无正式同级中枢、整体方向明确。
3. 核心三笔必须连续、已完成、方向交替、严格重叠。
4. 同时存在多个解释时，选择时间最早的合法核心；进入段因此被唯一确定。
5. 已提交给进入段或核心的笔不能再作为另一个并列正式中枢的拥有单位。

### 5.2 中枢核心

设核心三笔为 `U1/U2/U3`：

```text
ZD = max(U1.low, U2.low, U3.low)
ZG = min(U1.high, U2.high, U3.high)
```

只有 `ZD + epsilon < ZG` 时形成核心。核心一旦形成，在该级别修订内保持固定；普通延伸不重新扩大或缩小 L1 的 `ZD/ZG`。

进入段只用于确定上下文和方向，不参与上述交集。

### 5.3 中枢方向字段

中枢本身不能只保存一个含义模糊的 `direction`。至少拆分为：

```text
entry_direction           进入中枢系统的方向
core_formation_pattern    up-down-up / down-up-down
departure_direction       离开方向，未形成时为空
owner_movement_direction  所属走势方向，未判定时为空
```

界面可显示“下跌过程中的 L1 中枢”，但不能把“进入方向”“核心形成方向”“走势趋势方向”混为一谈。

### 5.4 正式、候选与显示条件

- 三笔重叠但没有合法进入段：`boundary_candidate`，默认隐藏。
- 进入段 + 三笔核心完整：形成正式中枢修订。最短通常至少涉及四笔，但进入段也可以由多笔组成。
- 中枢形成后，即使尚无延伸，只要后续产生完整离开与回试并形成可审计的第三类点，也必须显示该中枢，否则买卖点没有可见来源。
- 原始滑窗候选、被否决解释和历史修订只在诊断模式显示。

### 5.5 例一：上升过程中的正式中枢

价格端点：

```text
1, 10, 6, 15, 8, 20, 16, 25, 21, 30, 26, 35
```

从走势边界 `1` 开始：

- `1→10` 为进入笔。
- 核心三笔为 `10→6`、`6→15`、`15→8`。
- 三笔区间分别为 `[6,10]`、`[6,15]`、`[8,15]`。
- 正式核心为 `[8,10]`。
- `1→10→6` 的原始三笔交集不能另画一个正式中枢，因为第一笔已经是进入上下文。

### 5.6 例二：多笔进入段

价格端点：

```text
1, 5, 3, 10, 7, 15, 13, 20, 18
```

从走势边界 `1` 开始：

- `1→5→3` 为连续、整体向上、内部无正式中枢的进入段。
- 最早合法核心为 `3→10`、`10→7`、`7→15`。
- 核心区间为 `[7,10]`。
- `[3,5]` 虽可由最左侧三笔计算出原始重叠，但它占用了进入上下文，不能作为正式显示中枢。
- 后续 `15→13→20→18` 先进入离开/回试候选状态，不得重新滑窗生成并列中枢。

### 5.7 例三：转折后的下跌过程

局部端点：

```text
20, 14, 18, 13, 16, 8
```

- 下跌走势从 `20` 开始。
- `20→14` 是进入笔，不计入核心。
- 核心三笔为 `14→18`、`18→13`、`13→16`。
- 核心区间为 `[14,16]`。
- `16→8` 是离开候选。

因此核心既不是把进入笔算进去得到的 `[14,18]`，也不是把离开笔算进去得到的 `[13,16]`。

## 6. 中枢状态机

中枢形成后，所有后续单位必须按时间顺序进入唯一状态分支。

### 6.1 延伸

- 后续相关低级波动与固定核心 `[ZD,ZG]` 严格重叠时，中枢延伸。
- 延伸增加 `extension_unit_ids` 和外围包络，但不修改该级别初始核心。
- 暂时离开后，在独立新中枢或第三类点确认前返回原核心，仍归入原中枢的外围震荡过程。
- 单点触及不算严格重叠，也不能单独证明中枢已经离开。

### 6.2 离开与回试

- 离开段可以是一笔，也可以是内部无同级中枢的多笔走势段。
- 离开必须完整脱离核心，而不是盘中一度越过边界。
- 第一次反向完整低级走势构成回试段。
- 向上离开后回试低点严格高于 `ZG`，形成三买候选；向下离开后回抽高点严格低于 `ZD`，形成三卖候选。
- 回试重新进入核心，则离开失败，回到延伸/震荡状态。

### 6.3 同级新生中枢

后续必须在当前中枢系统之外形成一个具有自己进入段和三单位核心的完整同级中枢。只有下列条件同时成立，才作为独立同级新生：

- 新核心与旧核心严格分离；
- 围绕两个中枢的完整波动区间也严格分离；
- 新中枢没有复用旧中枢拥有的低级单位；
- 两者之间存在连续的连接走势段；
- 不跨越已确认走势边界、数据断点或待定隔离区。

### 6.4 中枢扩张与级别升级

若两个连续同级中枢的核心分离，但围绕中枢的完整波动区间发生重叠，则不能判为同级趋势，应进入高级别中枢候选。

升级必须满足以下任一完整证据路径：

1. 三个连续、已完成、递归合格的低一级走势严格重叠；
2. 两个连续同级中枢系统的外围波动重叠，并且连接关系足以形成完整高级别结构。

数量不是独立证据。九笔、九段或长时间延伸本身不能自动升级；只有这些单位能够被重新组织为完整的低级走势并满足高级中枢定义时，才允许升级。

业务上，升级表现为同一个活动 `center_family_id` 产生更高级别修订：

- `level` 提升；
- 时间范围和价格核心按高级别证据重新计算；
- 低级修订保留为组成证据；
- 默认视图只显示高级活动修订；
- 不能因后续任意重叠继续无限吞并所有历史中枢。

### 6.5 禁止传递吸收

以下推理非法：

```text
A 与 B 重叠
B 与 C 重叠
=> A、B、C 全部属于同一中枢
```

`C` 是否加入，必须重新以当前级别的完整单位、进入关系、核心关系和走势边界验证。中枢族不是区间图上的连通分量。

## 7. 走势类型与非同级别分解

### 7.1 基本结构

一个走势工作区可表达为：

```text
a + A + b
```

- `A` 为该走势包含的最高活动级别中枢系统。
- `a` 为进入段，可以低于 `A` 的级别。
- `b` 为离开段，也可以低于 `A` 的级别。
- `a/b` 可以是一笔或多笔无中枢走势段。

这正是本项目采用非同级别分解的主要原因：不强迫进入、连接、离开都先伪造成与中枢同级的完整走势。

### 7.2 走势方向

走势方向不能只由第一笔、最后一笔或单个中枢的进入方向决定。

- 一个同级中枢：分类为 `consolidation`。可以记录首尾价格形成的过程方向，但不能称为上涨趋势或下跌趋势。
- 两个及以上同级中枢：使用完整中枢系统的位置关系判定。
  - 后中枢 `DD > 前中枢 GG`：上涨及其延续。
  - 后中枢 `GG < 前中枢 DD`：下跌及其延续。
  - 核心分离但外围波动重叠：高级别中枢扩张，不是同级趋势。
- 不能满足上述任一关系：`classification=null`、`state=undetermined`。

其中 `GG/DD` 使用本中枢拥有的 Z 单位包络，不只比较矩形核心，也不包括进入、连接、最终离开和回试路径。Z 方向取初始核心第一、第三单位的方向；Z 单位只包括这两根与状态机已接纳的同向延伸单位。本文的“完整波动区间/完整波动包络”均采用这一口径（v26，依据 `../读缠论108课札记.pdf` 第123—124页），上下文另存 `context_low/high`，不得参与扩张。

扩张必须同时保存两个已形成同级子修订、连续且不重复的拥有单位、真实连接组件、至少一对分别属于两子的已确认 Z 单位严格重叠及首次证据可用时间；不要求所属走势完成。缺失证据或只接触时保持候选且不隐藏低级活动中枢。父核心取 `[max(left.DD,right.DD), min(left.GG,right.GG)]` 是周期内简化模型的工程约定，必须为正宽度；并非由原文关系定理唯一推出父级全部边界。

### 7.3 走势级别

- 走势级别由其内部最高有效中枢级别决定。
- 活动中枢从 L1 升级到 L2 时，其所属尚未完成走势同步产生 L2 修订。
- 这不是在同一区间额外创建一条竞争性的 L2 走势，而是同一个活动走势的级别修订。
- 已完成的低级走势仍保留，并可作为更高级结构的递归单位。
- 高级递归只能消费 `confirmed`、分类明确、边界完整、`recursive_eligible=true` 的低级走势。

### 7.4 走势开始与结束

- 数据左边界不是天然买卖点。没有结构锚点的早期单位可进入 `boundary_provisional`，但不能伪装成已确认走势。
- 趋势在第一类买卖点的真实点位结束；确认时间可晚于结束点。
- 盘整中枢被第三类买卖点破坏后，才确认有效离开；第三类点不机械等同于整个更高级走势完成。
- 二类买卖点主要确认第一次反向回撤，不默认切开一个完整走势。
- 所有正式边界必须位于真实低级单位端点，不能切开笔、中枢核心或已完成低级走势。
- 相邻走势可以共享一个价格端点，但不得共享整笔或整段源单位。
- 最右侧走势允许 `provisional`；数据结束、缺口、序列边界只能截断，不算走势完成。

### 7.5 边界选择优先级

当多个买卖点可能成为边界时，选择：

1. 时间最早；
2. 方向与前一走势相反；
3. 能使前一走势成为合法盘整或趋势；
4. 不切开中枢；
5. 不造成源单位重复归属；
6. 证据级别与当前分解层级一致。

不满足完整性时，保留候选点，但不提交正式走势边界。

## 8. 买卖点规则

### 8.1 第一类买卖点

第一类买卖点只属于趋势背驰：

- 必须已经存在至少两个同级、依次同向、系统波动互不重叠的中枢。
- 比较进入最后一个中枢前的同向离开段 `b` 与最后中枢后的同向离开段 `c`。
- 上涨趋势的 `c` 应先创新高；下跌趋势的 `c` 应先创新低。
- 背驰结论必须包含低级结构证据，MACD 仅作辅助，不得单独决定。
- 点位取 `c` 的真实极值端点。
- 反向低级走势完成后确认，`confirmed_at` 记录证据完成时间。

只有一个中枢时出现的力度减弱，标记为盘整背驰，不得冒充一买或一卖。

### 8.2 第二类买卖点

- 必须依赖已经存在的一类点。
- 一买后的第一次完整次级回调不跌破一买低点，形成二买。
- 一卖后的第一次完整次级回升不升破一卖高点，形成二卖。
- 二类点用于确认反转后的第一次回试，不默认结束新走势。

### 8.3 第三类买卖点

- 必须有一个已形成、可引用的中枢修订。
- 必须先有完整低级走势离开，再有第一次完整低级走势回试。
- 三买：向上离开后回试低点严格高于 `ZG`。
- 三卖：向下离开后回抽高点严格低于 `ZD`。
- 回试一旦进入核心，候选失效。
- 三类点确认的是中枢有效破坏与离开方向，不保证后续一定形成趋势，也可能进入更高级中枢。

### 8.4 盘整背驰

- 盘整背驰只发生在单中枢结构或中枢震荡中。
- 比较围绕同一中枢的前后同向离开段。
- 独立类型为 `consolidation_divergence_buy/sell`。
- 可作为候选转折与操作点，但不能直接把一个盘整改称趋势，也不能伪装成趋势一买/一卖。

### 8.5 力度证据

自动化引擎必须输出完整比较证据，至少包括：

```text
compare_segment_ids
price_amplitude
bar_span
average_slope
source_unit_count
internal_center_level
macd_area
macd_peak
new_extreme
structural_conclusion
auxiliary_indicator_conclusion
```

结构结论优先。若结构证据不足或不同辅助证据冲突，点保持候选或待定，不以单一阈值强制确认。

## 9. 高级别递归

### 9.1 递归单位

```text
笔 → L1 中枢 / L1 走势
已完成 L1 走势 → L2 中枢 / L2 走势
已完成 L2 走势 → L3 中枢 / L3 走势
...
```

- L2 不能直接再次使用笔构造。
- 未完成、待定、边界不完整或仅候选的低级走势不能参加标准递归。
- 三个连续低级走势形成高级核心时，仍执行与 L1 相同的进入段、连续性、严格重叠和唯一归属规则。
- 高级走势的进入、离开也允许是更低级的无中枢组件，保留非同级别分解特征。

### 9.2 中枢升级与递归新生的统一

同一区域若同时被“扩张路径”和“完成低级走势递归路径”识别为同一高级结构，应合并到同一个 `center_family_id` 的同一活动修订，并记录多条形成证据，不生成两个重叠的正式高级中枢。

### 9.3 递归终止

- 默认最高支持 L8。
- 没有足够已完成低级走势时停止。
- 实际最高级别由证据决定，不允许为了展示而补齐 L2/L3。
- 当前周期所有层级都必须明确标注为“周期内结构级别”。

## 10. 源单位归属不变量

任何一次计算都必须通过以下不变量：

1. 同一级别的正式中枢核心拥有单位不重复。
2. 进入段只属于上下文，不属于中枢核心拥有单位。
3. 离开和回试在状态未确认前不能被新旧两个中枢同时拥有。
4. 一个正式走势的所属中枢全部核心及扩展拥有单位，必须是该走势源单位的子集。
5. 用于确认前一走势的后续中枢或买卖点，不自动属于前一走势。
6. 相邻正式走势不共享完整低级单位。
7. 高级结构只引用低级结构，不删除或改写低级证据。
8. 任何结构不得跨越连续行情区间、序列边界、数据断点和待定隔离区。
9. 分页、缩放和筛选不能改变结构编号、归属、状态和边界。
10. 在底层已确认笔不变时，追加数据只能重算最后一个未确认边界之后的活动后缀；已确认前缀保持稳定。

## 11. 状态模型

### 11.1 中枢状态

```text
boundary_candidate
formed
extending
departure_candidate
retest_candidate
broken
promoted
closed
invalidated
```

中枢的 `formed` 只表示核心已经成立，不表示所属走势结束。

### 11.2 走势状态

```text
unassigned
provisional
confirmed
undetermined
truncated
```

- `confirmed`：边界由合法结构点确认。
- `provisional`：结构已形成但右边界未确认。
- `undetermined`：存在结构冲突或无法合法分类。
- `truncated`：被数据、缺口或序列边界截断，不等于完成。

### 11.3 结束原因

```text
first_buy_sell_point
third_buy_sell_center_break
higher_level_reclassification
data_boundary
sequence_boundary
provisional_tail
undetermined_conflict
```

其中只有与合法结构点对应的原因能够表示结构完成；数据边界和序列边界只能表示截断。

## 16. 测试计划

### 16.1 中枢选择

- 进入一笔 + 三笔严格重叠形成正式中枢。
- 多笔无中枢进入段 + 三笔核心形成正式中枢。
- 无进入段的左边界三笔只形成边界候选。
- 单点接触不成枢。
- 最早合法核心唯一，后续滑窗不得重复成枢。
- 进入段不属于核心拥有单位。
- 核心笔不能被两个同级正式中枢重复拥有。

### 16.2 状态机

- 延伸不改变 L1 固定核心。
- 暂时离开后返回继续原中枢。
- 完整离开与第一次回试产生三类点候选。
- 回试进入核心使候选失效。
- 同级新生与高级扩张命中互斥分支。
- `A-B`、`B-C` 重叠不能传递吸收 `A/B/C`。
- 九笔数量本身不能升级；完整递归证据可以升级。

### 16.3 走势与买卖点

- 单中枢只分类为盘整。
- 两个完整系统严格上移分类为上涨。
- 两个完整系统严格下移分类为下跌。
- 核心分离但外围重叠进入扩张，不判趋势。
- 单中枢力度减弱只产生盘整背驰，不产生一买一卖。
- 一类点结束趋势，点位日期与确认时间分离。
- 二类点不破一类点极值。
- 三类点确认中枢破坏，但不机械结束更高级走势。
- 无合法边界时保持 `provisional/undetermined`。

### 16.4 递归

- L2 只消费已完成、分类明确的 L1 走势。
- L2 不直接消费笔。
- 未确认 L1 走势不能参与 L2。
- 升级后默认只显示同一中枢族的活动修订。
- 高级结构生成后，低级证据仍完整可追溯。
- 追加行情不修改已确认前缀，只重算活动后缀。

### 16.5 真实行情回归

- 科创 50 日线不得再次被传递重叠吸收为覆盖 2020 至 2026 的单一巨型中枢。
- 科创 50 的每个正式中枢必须输出进入段、核心三笔、延伸、离开和回试证据。
- 对 2021-03-16、2021-05-11、2021-08-06、2022-04-27、2022-06-27 等争议日期，测试输出结构证据和未命中原因，不按日期写特例。
- 上证指数日线的重叠中枢必须区分延伸、同级新生和扩张，禁止按三段分组制造重复 L2。
- 分页前后同一结构的 ID、边界、状态和归属完全一致。

- 前端：`npm test -- --run`、`npm run build`。

## 17. 验收标准

1. 当前周期的笔是唯一 L1 基础单位，日线不依赖缺失的分钟数据。
2. 正式 L1 中枢必须有进入段和三笔核心；不再显示全局滑窗产生的大量三笔中枢。
3. 中枢核心、延伸、离开、回试和买卖点证据可以逐笔追溯。
4. 延伸、新生、扩张和级别升级具有互斥、可审计的判断路径。
5. 中枢升级表现为同一逻辑中枢的活动修订，不在默认图层叠加重复父中枢。
6. 不存在传递重叠滚成巨型中枢的情况。
7. 上涨、下跌只由至少两个同级中枢系统的严格位置关系确认；一个中枢只能是盘整。
8. 一、二、三类点与盘整背驰严格区分，MACD 不单独决定买卖点。
9. 走势端点来自真实结构点，点位时间和确认时间分离。
10. L2/L3 只消费已完成低级走势，不重复消费笔。
11. 无法确认的结构明确保持候选、未完成或待定，不使用默认值伪造结论。
12. 科创 50、上证指数真实行情回归、后端测试、前端测试、构建、数据库审计、API 检查和浏览器验收全部通过后，才允许切换活动快照。
