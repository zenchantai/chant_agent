## 1. 背景与总体目标

### 1.1 背景

当前系统基于股票已有的历史 K 线，按周期策略生成构件：日线、5 分钟和 30 分钟提供完整构件，周线、月线原生仅提供笔和 L1 笔中枢，并在默认模式独立叠加日线 L2 参考。用户希望增加一种训练方式：先指定一段已知历史，观察该区间形成的本周期结构，再逐根揭示后续 K 线，理解结构如何形成、变化、确认和失效。

训练关注的是“每个时刻根据当时已知数据能够得到什么结论”。例如，一个买卖点的价格位置可能出现在较早日期，但只有后续证据齐备时才能确认；训练必须呈现这个过程。

### 1.2 总体目标

在保持当前缠论算法和规则语义不变的前提下，建立两种业务模式：

1. **默认模式**：沿用现有工作台，基于股票当前可用的完整行情范围提供最新分析结果，不要求用户逐根回放。
2. **中枢交易训练模式**：以单只股票、单个 K 线周期和用户选定的已知历史区间创建训练，用户每次推进一根完整 K 线，系统更新当前可知的构件结果。

两种模式共用一套通用缠论构件引擎，分别管理输入范围、业务进度与持久化数据。业务模式 `analysis/training` 与计算策略 `full/pen_centers_only` 是两个独立维度；同一周期在两种业务模式中使用相同计算策略。

### 1.3 成功标准

- 当前 v27 的周期策略及其允许构件的判定规则保持不变，不为训练恢复周月完整递归、走势或买卖点计算。
- 相同已知输入、正式数据资格、连续区间、计算策略、参数和算法版本下，两种模式的原生构件结果一致。
- 训练不能提前使用尚未揭示的 K 线或其衍生构件、证据和报价。
- 单步推进采用增量更新和受影响范围重算；每步从头完整重算不能作为常规实现。
- 训练数据与默认模式数据隔离，不同会话和不同训练轮次之间互不污染。
- 用户能够保存、恢复、回退和重新开始训练，并查看结构变化及自己的判断记录。
- 本次训练先固定终点，到达后可由用户主动追加系统新增的完整 K 线。

## 2. 决策基线与范围

### 2.1 本次采用的产品决策

用户明确要求保留算法、共用核心、隔离数据、按已知区间初始化并逐根推进；用户要求按讨论中的建议形成需求文档。首版据此采用以下范围：

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| DEC-01 | 共用同一套缠论规则与计算核心 | 不为训练复制另一套算法，不根据模式改变成笔、成枢或确认条件 |
| DEC-02 | 首版为结构演化、判断记录与复盘 | 不包含模拟订单、持仓、撮合、盈亏或训练评分 |
| DEC-03 | 初始训练终点固定 | 创建时以系统已有的最新完整 K 线确定本轮终点 |
| DEC-04 | 到达终点后主动追加 | 新数据不自动延长当前轮次；用户点击追加后，仅延长终点，当前位置不变 |
| DEC-05 | 支持上一步、重新开始、保存与恢复 | 上一步恢复历史状态；重新开始建立新轮次，保留旧轮次 |
| DEC-06 | 用户起点就是计算起点 | 不自动读取起点之前的隐藏预热数据 |
| DEC-07 | 使用独立训练数据库 | 默认模式使用现有库；训练使用独立库，并进一步按会话和轮次隔离 |
| DEC-08 | 锁定行情与算法版本 | 已存在训练不随后台修订或应用升级静默改变 |
| DEC-09 | 首版使用完整 K 线 | 不训练单根 K 线内部的实时价格变化 |
| DEC-10 | 训练继承 v27 周期策略 | `5/30/d` 使用 `full`，`w/m` 使用 `pen_centers_only`；策略由服务端按周期确定并绑定会话 |
| DEC-11 | 首版训练不提供日线 L2 参考层 | 周月训练仅消费所选周期输入；后端不计算、不读取、不返回参考层，前端不保留参考对象、开关或缓存。默认模式参考层保留 |
| DEC-12 | 日线必须具备正式输入资格 | 创建和追加沿用当前日线完成证明规则；冻结时验证资格，历史推进不以真实登记时间截断历史 K 线 |

以上是首版需求口径。具体类名、内部表结构、接口命名和索引可在详细设计中调整，但不得削弱这些约束。性能数值的性质单独见第 14 章。

### 2.2 首版必须实现

- 默认模式与训练模式切换，以及原默认模式行为兼容。
- 从已有本地行情的单只股票创建训练；支持从自选列表进入。
- 周期选择：5 分钟、30 分钟、日线、周线、月线。
- 已知历史起止时间选择、实际 K 线边界回显、数据可用性检查。
- 已知历史区间初始化，按第 2.4 节的周期能力显示分型、笔、中枢；走势和买卖点仅适用于 `full`。
- 下一根、空格推进、上一步、返回本轮最远已揭示位置。
- 本步结构变化列表、构件证据查看、候选与确认状态区分。
- 训练标注、判断笔记、独立历史版本。
- 自动保存、会话列表、继续训练、历史回看、重新开始和删除训练。
- 到达固定终点后检查并主动追加新数据。
- 增量计算、检查点恢复、必要时的完整计算兜底与审计。
- 双模式隔离、防提前获取未来信息、并发与重复请求处理。

### 2.3 后续扩展，不纳入首版验收

- 模拟下单、持仓、手续费、滑点、盈亏、收益率和训练评分。
- 自动播放、倍速、一次跳过多根 K 线、任意未来位置跳转。
- 多股票组合训练、多周期联动训练、周月训练中的日线 L2 辅助参考源及低周期驱动高周期实时合成。
- 1 分钟、15 分钟、60 分钟、120 分钟、年线新增构件规则支持。
- 单根未完成 K 线内部的 tick 或实时预览训练。
- 随机选股、隐藏股票身份、竞赛、排行榜和多人协作。
- 用当前历史数据重建当年全部证券信息、公司行为知识和历史复权因子可得性的研究回测。

首版训练页隐藏现有 Agent 追问入口，避免调用未具备训练时点约束的分析接口。未来启用时必须满足第 7.5 节，不能直接复用默认分析上下文。

### 2.4 周期能力与图层边界

| 周期 | `calculation_profile` | 原生训练能力 | 不生成的原生构件 |
| --- | --- | --- | --- |
| 5 分钟、30 分钟、日线 | `full` | 分型、确认笔、各级中枢及关系、扩张升级、走势、背驰与结构买卖点，依当前规则和实际形成状态显示 | 不额外创造当前引擎未定义的构件 |
| 周线、月线 | `pen_centers_only` | 分型、确认笔、L1 笔中枢及形成、延伸、离开、返回、回试、破坏、新生等合法状态；保留内部进入/离开/回试证据 | 中枢扩张与升级、高级递归、走势、背驰、买卖点及其候选对象、扩张关系 |

- 周月原生最高级别不超过 L1；其走势、点和关系集合为空。内部证据组件不等于独立的组件图层，也不能借回试状态生成买卖点。
- 周月可显示原有普通 MACD、MA、BOLL 等指标；`pen_centers_only` 跳过用于结构判定的 MACD 证据和高阶链路，不等于删除图表指标。
- 日线 L2 参考属于跨来源显示叠加，不计入周月原生级别；首版训练明确不包含该叠加。当前默认模式仍按既有行为提供参考层。
- 本文后续出现“中枢升级、走势、买卖点、递归”等通用能力时，均受本表限制；不得将 `full` 的验收要求强加给周月，也不得为通过验收强开周月完整策略。

| 图表组件接收统一图表数据 | 可共用渲染与交互组件 | 增加训练控制器与数据源，隔离页面状态和缓存 |
| 图表分页默认每次最多 300 根 | 可按需加载显示数据 | 300 根是显示窗口，不能变成计算历史截断范围 |
| 绘图持久化主要按股票和周期区分 | 默认模式标注可保存 | 训练标注必须额外隔离到会话、轮次、步骤及修订 |
| 初始包含方向和尾部笔端点允许随后续证据调整 | 符合当前算法的动态修订行为 | 记录每一步观察结果，不能把“曾经显示”解释为永不变化 |

### 3.2 当前实现中与训练直接相关的边界

1. 当前历史图通常先获取完整结构快照，再按图形时间范围展示，不能将这种分页当作历史时点回放。
2. `process_inclusions` 在初始方向未明确时，会在本次输入范围内寻找后续方向证据。新增输入可能改变早期包含处理结果。训练必须限制输入前缀，同时保留这条原有规则。
3. `build_pens` 允许更极值分型触发端点修复。当前笔对象的 `confirmed` 字段不能单独作为“以后永远不可修改”的保证。
4. 当前买卖点图层主要按 `point_date` 选择显示位置。最终结果中的历史点位可能在更晚才被确认，仅裁剪位置会提前透露结果。
5. 分钟数据完整性主要按整个交易日检查。训练日内逐根推进时，尚未揭示的下午或后续分钟不能被判断为缺失。
6. 当前独立的行情报价、覆盖信息、绘图和 Agent 请求没有统一训练上下文，需要逐一隔离或关闭。
7. 当前前端代码中的自动刷新判断为 `timeframe === "1"`；不能根据历史描述推定所有周期已具备相同的前端刷新行为。
8. 既有中枢前缀测试使用预先生成的笔前缀；新增参考策略测试也不代表已经实现原始 K 线逐根训练的状态、恢复和隔离。
9. 默认周月投影按几何时间覆盖裁剪，不按历史训练 `as_of` 重算。晚形成的 L2、后来才出现的组成身份和父级关系都可能投影到早期图形，不能直接作为训练结果。
10. 日线资格、行情版本和覆盖信息都来自合格输入。未获确认的缓存行即使存在于行情表，也可能在正式输入中形成缺口；训练不能用原始行偷偷补齐。
11. 现有同源快照捕获和默认模式版本缓存可以作为参考，但不能复用其有写入副作用的 `ensure` 来代替训练独立存储和只读冻结。

| 1000 | 32.934 ms | 71 | 6 |

1630 根样本区间为 `2019-12-31～2026-09-18`。测量未包含行情读取、正式资格验证、落库、接口传输和浏览器绘图，不是多次统计或 P95，也没有证明分钟长序列或增量推进性能。这些数值不是 v27 或训练模式的当前性能证明，不用于替代第 14 章的新基准。

v27 已有独立发布验证报告，覆盖参考策略、正式日线来源和默认周月投影；该报告不包含训练会话验收。本次 1.1 文档更新仅进行了源码、运行版本及只读状态复核，没有执行业务实现、测试套件、构建或浏览器验收。

## 4. 术语与时间模型

| 术语/字段建议 | 定义 |
| --- | --- |
| 默认模式 `analysis` | 使用当前可用完整行情范围提供最新构件分析的业务模式 |
| 训练模式 `training` | 按已知历史初始化，并由用户逐根揭示后续行情的业务模式 |
| 计算策略 `calculation_profile` | 按周期固定的 `full` 或 `pen_centers_only`；与业务模式分离，不由训练用户任意切换 |
| 训练会话 `session_id` | 固定股票、周期、计算策略、计算起点、初始截止位置和规则配置的训练集合 |
| 训练轮次 `attempt_id` | 一次从初始已知区间开始的练习；重新开始生成新轮次 |
| 用户请求区间 | 用户在表单中输入的时间边界，可能落在非交易时间 |
| 实际计算起点 `start_bar` | 经过周期和时间边界规范化后实际纳入计算的第一根 K 线 |
| 初始已知截止 `initial_end_bar` | 进入训练时最后一根已知 K 线，作为第 0 步 |
| 当前训练位置 `cursor` | 本次显示和计算允许使用的最晚 K 线序号 |
| 最远已揭示位置 `revealed_max` | 当前轮次曾经揭示的最远位置，回退时不减小 |
| 固定训练终点 `target_end` | 当前轮次允许推进到的最后一根 K 线，只能显式追加延长 |
| 步骤 `step_no` | 从初始已知截止之后揭示的 K 线数量；初始化为 0 |
| 行情快照 `snapshot_id` | 固定内容、来源与价格口径的训练行情数据版本 |
| 已知时点 `as_of` | 当前游标对应 K 线的实际完成时间，按 Asia/Shanghai 解释 |
| 检查点 `checkpoint` | 可恢复计算状态，包含足够上下文及版本，不是单纯图形截图 |
| 价格发生时间 `point_date` | 极值或构件几何位置对应的历史时间 |
| 规则确认时间 `confirmed_at` | 原算法规定的证据齐备时间；不得因训练需要改写 |
| 行情证明登记时间 `market_confirmation_at` | 训练契约中对行情来源证明时间的独立命名；原表 `daily_bar_confirmations.confirmed_at` 的含义是实际成功获取或迁移/导入登记时间，不是构件确认时间 |
| 正式源资格 | 行情内容、来源和完成证明满足当前正式输入校验；创建或追加时按真实读取时钟验证，再冻结供训练使用 |
| 观察步骤 `observed_step` | 训练首次观察到某次新增、修订、确认或失效的步骤 |

`trade_date` 可能是周期标签，不一定直接等于该周期完成时间。周线、月线和分钟边界必须使用明确的周期归属与完成时间判断，不能仅以字符串日期比较代替。

真实冻结/采集时钟与历史训练 `as_of` 分离。合法历史行情可能在多年后才登记证明；不能要求 `market_confirmation_at <= 训练 as_of`，也不能把生产 `Store.clock` 替换成训练游标时间来筛选历史资格。已冻结的合格 K 线按其历史周期顺序揭示，构件的 `confirmed_at` 和 `observed_step` 仍按各自语义保存。

同一轮次应满足：

```text
start_bar <= initial_end_bar <= cursor <= revealed_max <= target_end
step_no = cursor 在快照中的序号 - initial_end_bar 在快照中的序号
```

这里的比较基于快照中排序后的有效 K 线序号，不是自然日加减。正常前进到新数据时 `cursor` 与 `revealed_max` 同时增加；回退只减小 `cursor`。

## 5. 两种模式的业务定义

### 5.1 默认模式

- 用户仍然通过现有自选股票和周期查看图表。
- 默认模式的“全量”是输入和展示语义：覆盖当前可用的完整合格行情，不要求用户从过去逐根推进；不表示所有周期都使用 `calculation_profile=full`。
- 此处不要求每次界面刷新都重新计算全部历史。行情未变化时可复用缓存，行情追加时可以共用增量能力。
- 当前规则、图层含义、已有标注和业务接口兼容性必须保留。
- 周月原生参考策略、默认开启的独立日线 L2 参考层及其当前交互继续保留，训练迭代不得删除默认模式已有参考能力。
- 默认模式不受训练的游标、起止范围、暂停、回退、删除或结束状态影响。

### 5.2 训练模式

- 每个会话仅对应一只股票和一个 K 线周期，策略按第 2.4 节固定；首版没有从属日线参考计算来源。
- 初始化只使用 `[实际计算起点, 初始已知截止]` 内的 K 线。
- 每次前进只加入下一根有效且完整的 K 线。
- 每一步都重新得到“当前已知范围下”的完整逻辑结果，但在计算执行上复用状态和未受影响部分。
- 每一步可能没有构件变化，也可能同时发生多种变化；不要求每一步强行产生新分型、新笔或买卖点。
- 到达当前 `target_end` 后停止前进；只有用户主动追加，才能扩大可推进范围。

### 5.3 跨模式一致性

两种模式的结果一致性要求建立在以下前提全部相同的基础上：

- 股票、K 线周期、实际计算起止边界。
- 原始输入数据、复权方式及价格基准。
- 正式输入资格、连续区间、日历解释与有效数据边界。
- `calculation_profile`、规则版本、计算实现版本及影响结构的参数。

训练起点晚于默认模式历史起点时，不要求两张图在终点处完全相同。不得为追求相同结果偷偷读入训练起点之前的历史。

上述一致性针对同周期原生构件和所选区间指标，不要求首版训练复制默认周月的日线参考层。训练不显示投影是本版已经确定的产品差异，不是算法不一致。

## 6. 用户流程与页面交互

### 6.1 进入与创建

从工作台提供明确的“默认分析 / 中枢交易训练”入口。进入训练后可以创建新会话或继续已有会话。

创建表单包括：

| 字段 | 要求 |
| --- | --- |
| 股票 | 从已有行情的股票选择，可从自选股票预填；不隐式修改自选列表 |
| 周期 | `5/30/d/w/m`，显示中文名称与可用范围 |
| 周期能力说明 | 根据周期展示“完整构件训练”或“笔与 L1 中枢训练”；周月说明首版没有日线 L2 参考层，不提供 profile 自由切换 |
| 已知起始时间 | 日线以上用日期；分钟线支持日期和具体周期时间 |
| 已知截止时间 | 定义第 0 步的右边界，不是最终训练终点 |
| 会话名称 | 可选；未填写时由股票、周期与初始截止日期生成 |
| 行情口径 | 展示当前复权方式和数据来源；首版沿用现有前复权 `adjustflag=2`，不新增切换能力 |

创建前展示实际首根、实际已知末根、已知根数、当前最新可训练完整 K 线及初始已知区间内的数据缺口情况。日线范围和根数基于正式资格过滤后的输入，最新可训练日期可能早于行情表最大日期。尚未揭示的后续区间只展示允许的终点日期和数量，不披露缺口明细。日期规范化不能静默超出用户请求范围。

无可用 K 线、起止倒置、截止超过最新完整 K 线、周期不支持时，明确提示原因并阻止创建。选定范围有 K 线但不足以构造分型或中枢时允许进入，说明“当前已知数据尚不足以形成相应构件”。

若初始截止等于训练终点，允许创建已到达终点的会话，用于查看已知结构，并提示目前没有后续 K 线可推进。

训练创建与推进只使用已同步到系统的行情，不在单步操作中隐式抓取外部行情或修复缺失数据。用户可通过现有行情管理功能补齐，再重新创建快照。

### 6.2 初始化画面

- 显示股票、周期、初始已知范围、当前已知截至时间、固定终点和推进进度。
- 展示当前已知 K 线、原有指标及合法构件。
- 第一屏默认靠近已知区间右端；向左加载不得越过训练起点。
- 起点前缺少上下文或指标历史不足时，按现有规则输出候选、未定或空值，不伪造完整结构。
- `full` 周期保留其内部 L1/L2/L3 等图层，级别不代表真实周线或月线；周月原生只提供笔和 L1 笔中枢图层，不出现走势、买卖点、原生高级中枢或独立组件图层。
- 分型/候选证据查看遵守所选策略。周月参考计算仍保留必要内部组件证据，但不能把这些证据渲染成被策略禁止的独立构件。
- 周月训练不显示“日线 L2 参考”的开关、数量、来源状态、空详情指引或检查器，不继承默认模式上次选中的参考对象。

### 6.3 下一根与快捷键

- “下一根”按钮与空格键执行同一操作。
- 一次有效操作只推进一根 K 线，跳过没有 K 线的休市或正常停牌时段。
- 忽略键盘长按产生的重复事件；输入框、文本编辑、弹窗及绘图拖动期间不触发推进。
- 请求处理中禁止重复提交推进，不累积不可见的多步队列。
- 构件、K 线、指标、详情、变化列表和进度必须对应同一成功提交的步骤，不能先移游标再等待计算。
- 失败时保留最后一个成功画面，展示可重试提示。

### 6.4 图表视野与对象选择

- 默认跟随最新揭示的 K 线，保持用户选择的可视根数与纵横缩放习惯。
- 用户向左回看图形后暂停自动跟随，提供“回到当前”按钮。
- “回到当前”只改变图表视野，不改变训练游标；“返回最远已揭示位置”才改变步骤。
- 推进不清空未保存的标注草稿或撤销栈。存在笔记或标注草稿时，先按操作前的步骤保存成功，再推进；保存失败则保留草稿并暂停本次推进，不能把草稿静默归入下一步。切换会话也要先保存或明确处理草稿。
- 对象仍存在时更新其当前修订详情；对象失效、被替代或不可见时明确说明原因，不能保留旧详情冒充当前状态。
- 原生中枢沿用当前周期展示约定：周线可视框、命中范围和 tooltip 使用三笔核心日期，选中强调核心三笔；月线保留完整中枢范围和相关延伸笔强调。此展示差异不改变冻结输入、构件状态或完整证据。
- 普通页面每次最多显示 300 根的约束不得截断引擎的完整已知历史。

### 6.5 构件演化与本步变化

页面提供“本步变化”列表，内容从所选周期策略的引擎输出与训练观察记录生成：

- 分型新增或相关证据变化。
- 笔新增、端点修订、候选状态变化。
- 两种策略允许的中枢形成、延伸、离开、返回、回试、破坏或新生。
- 仅 `full` 策略允许的中枢扩张、升级，以及走势状态、分类、边界和级别变化。
- 仅 `full` 策略允许的买卖点出现、确认或失效。
- 真实数据断点引起的结构分段。

变化名称必须有底层构件或证据支撑；无法细分时显示“结构已修订”及变化字段，不凭图形变化推测“升级”或“背驰”。同一变化可影响多个对象，界面可合并提示，底层仍保留完整明细。

列表点击可定位对象，说明价格发生时间、确认时间、本步发现时间和主要证据。图形仍画在真实价格位置，不把确认日替换为极值日。

候选和未完成结构以独立样式展示，可开关；必须复用当前规则产出的候选或诊断信息。若某类候选当前没有规范输出，应整理原有判定中间结果形成展示契约，不能新增一套训练专用成笔规则。

### 6.6 笔记与标注

- 用户可在推进前记录对当前结构及后续演化的判断。
- 笔记、绘图、修改和删除都保存所在步骤及修订，不与默认模式互通。
- 回到较早步骤时，只展示该步骤之前已存在的版本；之后创建、修改或删除的内容不反向污染历史。
- 当 `cursor < revealed_max` 时为本轮历史回看，首版不允许在旧步骤追写或修改判断；可返回最远已揭示位置继续记录，或重新开始一轮。
- 本轮已经看过的后市无法从用户记忆中消除，重新开始属于复练，不作为未看过答案的评分依据。

例如，第 20 步创建笔记、第 30 步修改：回到第 19 步时不可见，回到第 25 步时显示原文，回到第 30 步时显示修改后的内容；删除同样按修订步骤回放。在最远已揭示步骤给更早的 K 线添加标注时，创建步骤仍记为现在，不回填成那根 K 线的历史步骤。

### 6.7 上一步与返回最远位置

- 上一步最早只能退到第 0 步，不能撤销初始已知区间。
- 回退恢复当时的行情前缀、构件结果、观察事件及笔记/标注版本。
- 不改变 `revealed_max`，不删除已发生的步骤。
- 回退后再次前进，未超过 `revealed_max` 时恢复已保存步骤，不重复生成观察事件或写出另一套答案。
- “返回最远已揭示位置”可直接恢复本轮已看过的最远一步；不能跳到从未揭示的未来。

### 6.8 保存、恢复、重新开始与删除

- 每次成功操作后自动保存；刷新页面或重启服务后可以继续。
- 会话列表展示股票、周期、轮次、当前位置、固定终点、最近保存时间及是否可继续。
- 重新开始建立新的 `attempt_id`，从相同初始已知区间开始，使用所选旧轮次的行情快照与固定终点，不自动更新为系统最新数据。
- 新轮次不默认复制旧轮次的笔记和标注；旧轮次保留并可独立回看。同一会话只有当前轮次可修改，被替代的旧轮次转为只读；如需以旧轮次的数据重新练习，应从其快照创建新轮次，不恢复旧轮次为另一个可写分支。
- 删除会话前明确展示删除范围。只删除该会话的训练数据；被其他会话引用的快照不能删除。
- 切换回默认模式时恢复该模式原来的股票、周期、视野和标注，训练进度保留。

## 7. 行情范围、完整性与防未来规则

### 7.1 已知范围硬边界

任意步骤 `t` 的引擎输入必须严格限制为该轮快照中的 `[start_bar, cursor(t)]`。严禁以下做法：

- 用全部未来 K 线计算最终结构，再在前端遮挡。
- 用最终中枢或走势的日期字段裁剪，冒充当时已经形成。
- 用完整未来走势确认的买卖点填入过去步骤。
- 向引擎附带未来 MACD、未来笔或未来覆盖区间作为辅助证据。

训练快照可在服务器保存后续待揭示原始行情，但计算入口与当前步骤响应只能访问许可的前缀。首版不预先生成并下发未来完整结构。

### 7.2 起止规范化与完整 K 线

- 时间统一为 Asia/Shanghai；接口使用包含明确时区语义的时间值。
- 日线、周线和月线按其交易周期归属选择完整观察；日期型左边界对应周期标签范围，日期型右边界还必须验证实际周期完成时间不晚于所选日结束。
- 分钟线按完整时间戳选择，显示实际纳入的第一根和最后一根。周期标签与起止时间的映射必须固定且可测试。
- 周/月 K 线只有在对应交易周期结束并有可靠完整性依据时才可揭示。不能因为数据库存在一行就认定它已经收盘。
- 日线必须先满足第 7.6 节的正式输入资格，不能只凭历史日期、交易日历或时间跨过收盘判断为完整。
- 其他周期沿用当前周期完成判断；若没有可靠完成标记，应结合交易日历和周期边界验证，无法证明完整的末根不进入训练终点。不把日线专属证明表强行当作周月或分钟资格机制。
- 规范化不自动扩大用户的已知时间上界。没有符合条件的完整 K 线时提示调整范围。

### 7.3 连续区间与缺失数据

训练的预期数据范围由“用户选定区间与当前已知时点以内的交易时段”共同确定：

- 左边界之前属于用户主动截断，不属于缺失。
- 当前已知时点之后属于尚未揭示，不属于缺失。
- 区间内部应存在而缺失的数据才是实际缺口。
- 日线原始表中存在但未获有效正式资格的记录不能参与填补缺口；连续性与覆盖检查必须基于同一批合格输入，不能与未过滤原始行混用。
- 休市和有依据的停牌与行情缺失分开处理；不合成虚假 K 线填补。
- 保留原有行情缺口、数据断点和序列边界的语义及识别规则。正常价格跳空按既有规则处理，不能笼统等同于数据丢失。
- 已证明的断点必须传入共同引擎，构件按现有规则处理，不为训练连续感强行跨越。

例如，5 分钟训练推进到某日 `10:05`，该日 `10:10` 之后的 K 线不计为缺失；若 `09:55` 应有数据却不存在，则属于已知范围内的真实缺失。

已确认的真实缺口允许用户带提示训练，并按规则分段；若缺口与停牌无法区分且会影响计算边界，创建或推进应暂停并提示补齐依据，不能暗中假设连续。分钟连续区间必须支持精确时间边界，不能只按日期切片。

### 7.4 行情快照与复权

- 创建时在同一一致性读取视图中，冻结从计算起点到固定终点的合格原始行情内容、顺序、来源、复权方式、价格基准、正式资格证明和必要日历/连续性依据。
- 冻结内容必须能恢复实际数据，只有行情哈希或当前市场表引用不足以保证重现。
- 默认模式后台继续同步行情，不得更新已冻结训练内容或资格证据。后来默认库确认失效，不反向改写旧训练；是否还能追加需独立按第 8 章重新校验。
- 使用当前前复权历史快照进行逐根构件训练，只保证固定行情口径下的时点输入约束；不承诺重建当年实际可得的全部复权因子或公司行为信息。
- 影响训练结果的行情、正式资格、连续性信息、计算策略或计算参数变化必须形成新版本，不得原地替换。
- 训练清单的 `snapshot_id` 与源行情行的 `snapshot_id` 必须明确区分。后者属于现有日线证明哈希中的来源字段，复制时不得用训练清单 ID 覆盖；内部可用 `training_snapshot_id/source_snapshot_id` 等名称消除歧义。

### 7.5 防提前获取信息的覆盖面

| 入口 | 必须遵守的边界 |
| --- | --- |
| K 线、指标、成交量 | 仅返回已揭示前缀；均线等不能读取起点前隐藏数据 |
| 分型、笔、中枢、走势、买卖点 | 仅返回当前输入实际产生的结果及其当前可知证据 |
| 历史修订、关联对象、诊断 | 不得引用尚未揭示的构件、未来端点或未来确认结果 |
| 原生展示目录与父级证据 | 只能从当前步骤结构生成活动/组成身份及父级关系，不能从默认最新结构补齐证据 |
| 日线 L2 参考层 | 首版训练服务不请求日线参考源，不调用默认投影生成路径；响应、前端状态、缓存和详情都不得包含参考对象 |
| 顶部报价、涨跌幅、最新价 | 从已知行情计算；没有足够上下文时显示空值，不能读取实时报价补齐 |
| 自选侧栏 | 训练工作区不显示其他股票实时涨跌等会干扰历史环境的信息；股票入口可保留 |
| 分页、缩放、数据范围详情 | 不返回未揭示 OHLC、未来结构数量、价格极值或覆盖诊断明细 |
| 笔记、标注及其修订 | 仅显示当前步骤可见的版本 |
| Agent 分析 | 首版隐藏；后续必须仅接收会话的已知数据与证据，不调用默认全量分析路径 |
| 错误信息、导出或调试响应 | 不附带未揭示行情和完整未来快照 |

固定终点日期、总步数、剩余步数和“可追加 N 根”的数量允许作为训练管理信息展示。这些许可不包含未来价格、构件、信号和缺口明细。快照标识使用不透明标识即可，不把未来数据内容放入前端状态。

此约束针对训练系统的计算、接口和展示。用户主动切换默认模式或访问外部行情查看后市，不属于首版需要阻止的行为，也不应因此宣称用户仍未看过未来。

### 7.6 正式日线资格、证明与两种时钟

1. **资格判断沿用 v27**：日线创建范围、初始已知输入、固定终点和追加列表均以 `confirmed_daily_bars` 等价的正式资格为准。资格适配逻辑应可对只读采集结果验证，不调用会写默认库的 `ensure` 或补证明路径。
2. **证明绑定具体内容和来源**：按股票、复权方式和日期匹配证明，使用既有 `_daily_bar_hash` 语义验证 OHLC、量额、复权因子、停牌、涨跌停及 `source/snapshot_id/source_revision` 等字段；SQLite 行 ID 不参与。不能只比较收盘价或忽略来源修订。
3. **读取时的时间约束**：现有资格要求该日确认边界（上海时间 `15:00:15`）不晚于证明登记时间，且登记时间不晚于真实读取时钟。冻结时采用真实读取/采集时钟，不采用历史训练 `as_of`。
4. **新取得证明的条件**：沿用现有成功获取并匹配实际入库内容的规则；当日请求必须在确认边界后发起，并有正向交易日历依据。在 `15:00:14` 发起、`15:00:15` 返回的请求不因此满足资格。被拒收的来源数据或失败请求不能给另一份缓存登记完成证明。
5. **保留历史兼容路径**：现有一次性迁移基线和合法的新历史导入可提供正式资格；不要求所有历史数据重新联网获取。历史导入不等于每根都有原始网络请求日志或完整正向日历，资格按现有历史路径校验，不编造缺失证明。
6. **缓存不会自动转正**：盘中缓存或失效确认行不会仅因收盘、跨日、重启或恢复旧价格而重新合格；须按现有合法确认路径重新取得证明。
7. **冻结内容可追溯**：训练保存原证明键、内容哈希、`market_confirmation_at`、真实冻结验证时间、资格策略版本及必要日历/连续性依据。现有表未保存的原始请求或证明途径不得伪造；只有实际可得的附加证据才能记录。
8. **历史推进与登记时间分离**：例如一根 2019 年的日 K 线在 2026 年导入或迁移时确认，冻结验证通过后仍能用于其所属历史区间。推进仅按快照顺序和周期完成时点揭示，不要求它的真实登记时间早于历史游标。
9. **资格变化也属于输入变化**：即使价格未变化，新取得或撤销资格都可能改变可用输入、缺口、最新可训练位置及结果。创建和追加需重新核验候选输入资格，但每一步直接使用已冻结版本，不回查默认库改变历史。
10. **一致性读取**：从默认库采集行情、确认记录和日历/覆盖依据时使用同一只读一致性视图，防止旧行情与新证明混合。训练服务不得为取得资格而迁移、补写或清理默认库。

此规则保证固定合格行情口径下的结构训练，不把真实登记时间解释为当年信息实际可得性；第 2.3 节对历史研究回测的范围限制继续适用。

## 8. 固定终点与主动追加规则

### 8.1 初始固定终点

创建时在一致的数据视图中选择系统已经拥有且符合当前周期正式输入要求的最新完整 K 线，记为该轮次 `target_end`。日线不能直接取 `market_bars` 最大日期。后台出现新 K 线或新确认，不自动修改本轮终点、步骤总数或当前结果。

“固定终点”不等于禁止继续训练；它表示本轮范围只有在用户明确操作后才扩展。

### 8.2 到达终点

当 `cursor = revealed_max = target_end` 时：

- 页面显示“已到达本轮终点”，下一根不可用。
- 提供“检查新数据”入口；新数据指默认行情库已同步的、此前终点之后的完整 K 线。
- 没有新数据时保持原状态；有新数据时只提示可追加范围和数量。

### 8.3 追加过程

用户选择“追加新数据，继续训练”后：

1. 校验请求仍针对当前会话、轮次和已到达的终点。
2. 在同一一致性视图获取当前系统已经同步且具备所需正式资格的完整新增 K 线、证明及必要日历/连续性依据。
3. 验证旧快照对应前缀的行情内容、来源身份、价格基准、连续性和正式资格仍相容。来源或复权字段变化不能统一当作无关元信息；同内容、同来源、同资格下的合法重复确认仅更新登记时间，可以视为相容，不改写已冻结证明。若前缀或必要证明无法读取验证，也不能盲目拼接。
4. 校验追加段排序、重复、连续性、完整性和所选计算策略；不追加未经有效确认的日线缓存。
5. 创建新的不可变快照清单，可复用原有数据块，保留旧清单。
6. 原子更新本轮快照引用、追加记录与 `target_end`。
7. 保持 `cursor`、`revealed_max`、当前构件和已保存笔记不变。
8. 恢复下一根能力，由用户继续逐根推进。

追加请求只在当前位于本轮固定终点时可执行。正在回看历史时需先返回已到达的终点，不在后台偷偷修改当前轮次。

### 8.4 历史修订和价格口径不相容

若源行情修订了旧 K 线、前复权基准改变、正式资格失效、必要来源/连续性依据变化或旧前缀无法证明相容：

- 本次追加失败，不修改旧快照、终点和训练结果。
- 明确告知“当前系统行情版本与本轮训练快照不一致”。
- 允许用户基于新行情版本创建新的训练会话；原会话保留回看能力。
- 不将旧价格基准历史与新基准新增数据直接拼接，不自动重算旧步骤。

### 8.5 示例

假设初始已知区间为 `2024-01-02～2024-06-28`，创建时系统最新完整日 K 线为 `2026-09-18`。后台后来同步到 `2026-09-21`：

- 本轮仍先推进到 `2026-09-18`。
- 到达后选择追加，终点变为 `2026-09-21`，图表与当前位置仍停在 `2026-09-18`。
- 再按一次空格才揭示下一根日 K 线。

日期仅用于说明流程；实际推进以数据中的交易 K 线序列为准。

## 9. 业务状态、修订与失败处理

### 9.1 状态模型

持久化状态至少区分：

| 状态 | 含义 | 允许行为 |
| --- | --- | --- |
| `initializing` | 正在冻结数据并构造第 0 步 | 查看进度、查看失败原因，不允许推进 |
| `ready` | 初始化成功，可回看或继续 | 前进、后退、记录、保存、重新开始 |
| `at_end` | 当前游标到达固定终点 | 回看、检查新数据、追加、重新开始 |
| `read_only` | 旧轮次已被替代，或原计算版本/状态兼容条件不满足；保存具体原因 | 回看已保存步骤，不修改旧记录或执行新推进 |
| `failed_initialization` | 第 0 步未成功建立 | 重试创建或删除失败记录，不显示半成品结果 |

`computing/restoring/extending` 可以作为请求中的临时忙碌状态，不应覆盖最后一次成功的持久化游标。常规操作失败后保持原有效状态，并记录失败原因。

回退离开终点后可恢复为 `ready`，但追加仍必须满足第 8 章的游标条件。这里的 `ready` 不代表原运行时永远可用，仍需检查版本兼容性。

### 9.2 构件修订规则

- 原引擎决定结构何时形成、确认、修订或失效，训练层不改变判定。
- `full` 才产生高阶递归、走势和买卖点修订；周月仅记录其原生允许构件与状态变化。日线 L2 的活动/组成身份和父级引用不属于首版周月训练数据。
- 区分结构自身的 family/revision 与训练“第几步观察到”的历史记录；两者不能混为一份最终状态。
- 价格发生时间、规则确认时间和训练观察步骤分别保存，不相互覆盖。
- 原算法允许端点修正时，更新受影响结构并保留旧步骤；不能强制冻结原算法仍允许修订的对象。
- 同一 family 在不同步骤的身份需要稳定关联；若基础 ID 因端点变化而改变，训练层记录明确的替代/修订关联，不能仅凭数组序号认定同一个对象。
- 构件被升级吸收或失效时，其历史证据仍保留；当前视图遵守现有活动修订规则。

### 9.3 幂等、并发和事务

- 修改请求携带 `session_id`、`attempt_id`、`command_id` 和 `expected_revision`。
- 同一命令重试必须返回同一已提交结果，不重复推进、追加、创建笔记或建立轮次。同一 `command_id` 携带不同操作参数时应拒绝，不能覆盖原命令记录。
- 不同命令携带旧 revision 时返回明确冲突，前端刷新当前状态；不得静默覆盖另一个标签页的结果。
- 同一会话的状态修改串行提交，旧轮次修改请求必须拒绝；不同会话可以独立计算。
- 行情引用、游标、结果、事件、检查点及命令结果的持久化应保持事务一致。
- 若计算放在事务外进行，提交前再次校验 revision；失效结果不得覆盖新状态。
- 只有服务端成功提交后，前端才显示新一步。网络超时无法确认是否成功时，按相同命令 ID 查询或重试。

## 10. 通用引擎与技术架构约束

### 10.1 分层职责

| 层 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 行情输入适配层 | 选择范围、规范化时间、验证正式资格与连续性、提供合格完整 K 线 | 判定成笔、成枢、走势结束或买卖点 |
| 通用构件引擎 | 共用包含、分型、笔；按 profile 计算允许的中枢、走势、买卖点及校验 | 抓取行情、读写默认库、处理用户页面状态、因业务模式擅自切换 profile |
| 默认模式服务 | 提供完整已知行情、维护默认模式结果 | 读取训练会话状态来改变默认结果 |
| 训练模式服务 | 管理快照、游标、轮次、单步、观察记录、恢复和追加 | 复制或改变缠论规则 |
| 存储适配层 | 在各自数据域事务保存和读取 | 自动把训练结果激活为默认活动 run |
| 图表与交互层 | 共用渲染，显示当前步骤及证据 | 用未来全量数据在前端自行模拟时点隔离 |

引擎本身不根据 `analysis/training` 改变判定规则；允许且必须保留 v27 的 `calculation_profile` 分流。服务端按周期确定策略，创建、追加、恢复和接口请求都应拒绝周期/策略不匹配。显示模式和参考层由业务服务管理，首版训练不接默认周月日线投影服务。

### 10.2 引擎能力契约

以下为能力示意，不限定最终函数名称：

```text
initialize(known_bars, analysis_context)
    -> engine_state, current_result

append_bar(engine_state, next_bar, current_context)
    -> new_state, current_result_or_delta, structural_changes

checkpoint(engine_state)
    -> versioned_checkpoint

restore(versioned_checkpoint, retained_history)
    -> engine_state
```

`analysis_context` 至少包含周期、`calculation_profile`、已知输入范围、正式资格与冻结版本标识、连续区间/日历解释版本、规则版本、计算参数和必要价格口径信息。K 线必须保留当前算法实际使用的字段，不能将输入简化成只有收盘价。底层引擎接收已验证、已裁定为已知的输入及必要上下文，不自行查询默认库或把整个未来资格/行情清单当作计算输入。

批量入口和增量入口共用相同的规则判定函数、对象语义及校验器。批量入口既服务默认初始化，也作为增量结果的正确性对照。

### 10.3 默认模式重构边界

- 将当前散布于服务编排中的构件计算组织为统一入口，保持默认模式请求与结果兼容。
- 保留 v27 周期策略、正式日线输入选择，以及默认周月独立日线参考的获取、映射、分页版本和展示契约。训练禁用参考层不得改变默认模式参考开关、对象选择或来源状态。
- 未变化行情继续使用版本缓存；正常新增行情可使用相同增量能力。
- 默认行情发生历史修订时，从最早变化位置失效重算；无法证明局部安全时执行完整计算。
- 默认模式保持最新分析职责，不因此新增用户可见回放步骤。
- 训练服务不得实例化会自动初始化或迁移默认业务库的写入对象来完成只读行情获取。

## 11. 增量更新、恢复与正确性

### 11.1 常规更新策略

1. 处理新 K 线与当前未稳定的包含区间，维护未决初始方向上下文。
2. 更新相关分型及笔端点候选，保留原算法可能重新使用的候选证据。
3. 找到最早变化的基础构件，标记所选策略允许的依赖对象失效；周月仅涉及原生笔、中枢和必要内部证据，`full` 还涉及走势、买卖点和高级结构。
4. 重算受影响的工作区；仅在 `full` 中沿高级递归依赖传播变化。周月不得调用升级、走势、点或背驰链路。
5. 复用已证明不受影响的前缀与缓存；维护显示用指标状态，以及 `full` 所需的 MACD 等结构证据状态，并保持各自的断点重置语义。
6. 校验当前结果，保存本步结果增量、观察事件及必要检查点。

不能按固定最后 N 根 K 线或固定最后几个中枢替代安全边界证明。不可承诺每一步都只影响最后一个对象或具有固定 O(1) 成本。

### 11.2 完整计算兜底

允许在初始化、检查点或增量状态无法恢复、无法证明安全重算边界或检测到一致性问题时，对**当前已知前缀**执行完整计算。前提是会话绑定的计算版本仍可运行，或已按第 12.4 节完成明确的兼容验证；不能借“完整计算兜底”用不兼容的新算法继续旧会话。

- 兜底记录原因、影响范围、耗时和结果版本。
- 不允许因性能或错误恢复而读入未揭示数据。
- 不能将每步完整重算包装成增量接口后宣称满足需求。
- 若增量与批量结果不一致，不直接发布增量结果；使用通过校验的批量结果维持本步正确性，并记录需要修复的问题。
- 若批量结果也不能通过现有校验，停止提交本步，保留旧状态；不得为了推进成功而修改缠论规则。

### 11.3 一致性标准

对每个受测前缀，在行情与正式资格快照、连续区间、`calculation_profile` 和算法版本一致的条件下：

```text
incremental_result(start..cursor)
    等价于
batch_result(start..cursor)
```

比较范围包括包含处理结果、分型、笔端点与确认时间、组件、中枢核心和包络、family/revision 关系、构成证据、走势边界与分类、买卖点、各类对象活动状态、关联关系、诊断，以及指标数值、指标断点重置状态和结构断点语义。

按策略验证实际允许的对象；周月对不生成的高级构件、走势、点和关系集合验证为空，而非跳过检查。原生结果比较不包含默认模式的日线 L2 参考层。正式资格选择在输入适配层单独对照：不能用不合格输入算出一致结果就认定整个训练链路正确。

允许排除会话 ID、数据库主键、保存时间、执行耗时等不影响结构的业务元信息。浮点比较遵守现有规则精度，不得扩大容差掩盖成枢、重叠或确认差异。

### 11.4 检查点与历史恢复

- 初始化后建立第一个检查点，后续按策略周期性保存，可结合重大结构变化保存。
- 检查点包含构件状态、未决上下文、指标状态、输入范围、`calculation_profile`、资格/连续性快照引用及所有版本信息；不能跨策略恢复计算状态。
- 历史步骤以不可变结果增量或修订保存，结合检查点可准确重建当时画面。
- 前向业务事件不一定足以逆向恢复，不能假定只保存“中枢升级”文字即可还原旧结构。
- 恢复时校验检查点校验和、前缀行情版本和状态格式；损坏检查点可尝试更早的有效检查点，不允许静默丢弃训练记录。
- 仅需查看已保存历史时，应可从物化结果与增量恢复，不强制依赖旧计算代码重新运行。

## 12. 数据隔离、持久化和版本管理

### 12.1 隔离方案

| 数据域 | 位置建议 | 要求 |
| --- | --- | --- |
| 默认行情及默认分析 | `data/chant_agent.db` | 保留现有业务归属 |
| 训练持久化 | `data/chant_training.db` | 独立数据库连接、事务、迁移和清理策略 |
| 训练大体积快照（若外置） | 独立训练数据目录 | 内容不可变、清单可追踪，不能引用会被默认清理删除的临时文件 |

首版优先在训练库保存原始行情快照，避免引入不必要的文件与数据库双写；如采用外置数据块，必须保证原子引用、校验与完整备份。

默认行情、日线证明和必要日历可被训练以一致性视图只读采集，之后以训练快照计算。训练不得写入 `daily_bar_confirmations` 或触发该表迁移，也不从默认活动日线 run 获取参考层。默认同步进程继续独立运行；隔离验收不能把后台合法行情更新误判为训练写入。

### 12.2 逻辑实体

以下为最低信息要求，物理表可以合并或调整：

| 实体 | 主要信息 |
| --- | --- |
| `training_sessions` | 会话 ID、名称、股票、周期、calculation_profile、起点、初始截止、规则与参数、当前轮次、会话 revision |
| `training_attempts` | 轮次 ID、会话 ID、来源轮次、快照清单、cursor、revealed_max、target_end、状态、创建与更新时间 |
| `training_snapshots` / `training_bars` | 合格原始 K 线、顺序、来源字段、复权与价格基准、资格及日历/连续性依据、内容校验和、父清单与数据块引用；训练清单 ID 与源 snapshot_id 分开 |
| `training_market_proofs`（可并入快照） | 原证明键、原 row_hash、market_confirmation_at、真实冻结验证时间、资格策略版本及实际可得证据；不伪造未留存的原始请求日志 |
| `training_steps` | 轮次与步骤、当前截止、前缀版本、状态摘要、结果哈希、提交版本、计算统计 |
| `training_structure_revisions` | 构件及其前后版本、原算法身份、当前活动状态、观察步骤、替代关联 |
| `training_events` | 本步新增/修订/确认/失效事件、关联对象与证据、事件唯一标识 |
| `training_checkpoints` | 轮次、步骤、格式版本、计算版本、calculation_profile、资格/连续性快照引用、完整状态与校验和 |
| `training_note_revisions` / `training_drawing_revisions` | 会话、轮次、对象 ID、创建步骤、修订步骤、内容、删除标记 |
| `training_extensions` | 追加前后清单、终点、新增范围、兼容性校验、命令 ID |
| `training_commands` | 幂等键、预期 revision、操作类型、提交结果与状态 |

每个训练业务查询必须校验会话和轮次归属。构件 family 标识在不同会话中相同，也不能被当作同一条业务记录覆盖。

### 12.3 存储增长与清理

- 不要求每推进一根都保存一份全部历史构件副本；常规采用修订/增量加周期检查点。
- 同一不可变行情快照可供不同轮次复用，保留引用计数或等价引用追踪。
- 保存历史物化信息应足以在旧运行时不可用时回看，不以省空间为由只保存无法恢复的摘要。
- 不自动裁剪仍在使用的历史步骤、笔记或证据。
- 删除训练时仅清理其专属记录和无人引用的训练快照，不能级联到默认模式行情、构件、自选或绘图。
- 备份必须覆盖训练数据库及其 WAL 状态；外置快照存在时一并备份并验证可恢复。

### 12.4 规则与实现版本

至少保存 `definition_version`、`calculator_fingerprint`、`calculation_profile`、正式资格策略版本、资格/日历/连续性输入版本、影响算法的参数、`snapshot_schema_version`、`checkpoint_schema_version` 和结果格式版本。

- 规则版本相同但计算指纹变化，不自动视为检查点可继续使用。
- 周期策略或正式资格契约改变也属于兼容性变化；不允许用 `full` 恢复原 `pen_centers_only` 轮次，或用较宽松资格静默补齐旧输入。
- 有明确验证的兼容迁移时，可以保留来源记录后迁移状态；不能重写原步骤结果。
- 没有兼容方案且旧运行时不可用时，旧会话进入可回看状态，新推进和需要新计算的重启暂停。
- 用户可另建使用新计算版本的会话，不静默混用不同版本结果。
- 不能承诺仅保存一个指纹就能永久执行旧算法；实现阶段必须明确支持的运行时保留与迁移策略。

## 13. 服务接口与前端上下文契约

### 13.1 服务能力

推荐使用独立训练路由。以下为可落地的能力范围，路径名称可在详细设计中调整：

| 方法与路径建议 | 职责 |
| --- | --- |
| `GET /api/training/availability` | 查询指定股票周期、固定策略、具备所需资格的可用范围、最新完整 K 线和创建前校验信息 |
| `POST /api/training/sessions` | 冻结输入、创建会话与首轮、建立第 0 步 |
| `GET /api/training/sessions` | 查询会话列表与当前保存位置 |
| `GET /api/training/sessions/{id}` | 查询会话及轮次元信息 |
| `GET /api/training/sessions/{id}/chart` | 查询指定合法已揭示步骤的图表分页 |
| `POST /api/training/sessions/{id}/step` | 向前一根或向后一根，校验轮次与 revision |
| `POST /api/training/sessions/{id}/restore` | 恢复当前轮次内已揭示的某个保存状态；首版 UI 仅提供已定义的恢复入口 |
| `POST /api/training/sessions/{id}/restart` | 创建新轮次，保留旧轮次 |
| `GET /api/training/sessions/{id}/extension-preview` | 在到达终点后查询可追加范围与兼容性，不返回未来 OHLC |
| `POST /api/training/sessions/{id}/extend` | 主动扩展快照与固定终点，保持游标不变 |
| `GET/POST/PATCH/DELETE /api/training/sessions/{id}/notes` | 训练笔记读取与版本化修改 |
| `GET/POST/PATCH/DELETE /api/training/sessions/{id}/drawings` | 训练绘图读取与版本化修改 |
| `DELETE /api/training/sessions/{id}` | 按明确范围删除训练，不影响其他数据域 |

修改与删除单个笔记/绘图时还必须提供并校验对象 ID；REST 路径可具体细化。创建、重启、追加和删除同样需要幂等语义。

### 13.2 响应上下文

训练图表响应至少携带：

```text
mode, session_id, attempt_id, session_revision
symbol, timeframe, adjustflag, calculation_profile
initial_start, initial_end, cursor, revealed_max, target_end, step_no
as_of, status, has_next, has_previous
snapshot_id, definition_version, calculator_fingerprint, result_version
input_eligibility_version, continuity_version
market, indicators, structure, changes, notes, drawings, pagination
```

`has_next` 依据当前轮次已经固定的范围判断，不因默认行情库后台更新自动变化。`before` 分页必须同时受 `start_bar` 与当前步骤限制。对超出 `revealed_max` 的步骤查询必须拒绝，不能仅依赖前端按钮禁用。

资格与连续性版本使用不透明标识；当前步骤只返回已揭示范围所需的证据说明，不返回未来资格清单。首版训练图表不包含 `overlays.daily_l2`，也不通过错误、诊断或详情附带日线参考源数据。服务端根据会话固定策略校验请求，客户端不能通过传入 `full` 改变周月能力。

### 13.3 前端状态隔离

- 数据请求、缓存、缩放、图层偏好、对象选择、绘图草稿和撤销栈以模式、会话和轮次进行命名空间隔离，并校验计算策略与结果版本。
- 切换模式、会话、轮次或回退步骤时取消旧请求；仅接受上下文和 revision 匹配的响应。旧默认模式响应、旧会话响应及回退前的较晚步骤响应不得短暂覆盖当前画面，不能出现一帧未揭示行情。
- 推进后用新修订更新选中对象，不保留指向旧对象实例的过期详情。
- 训练页不启动默认行情刷新或实时报价请求；默认模式后台同步服务本身无需停用。
- 进入训练清理旧参考对象选择，不合并默认模式 `daily_l2` 缓存，不显示参考开关、计数、来源提示或详情占位；返回默认模式后按默认上下文恢复其参考能力。
- 多标签页收到版本冲突后以服务端状态为准，不自动再次追加一步。

### 13.4 错误分类

至少区分输入范围错误、周期不支持、周期/策略不匹配、无完整或无合格正式数据、证明失效、连续性不可判定、行情版本不相容、已到终点、版本冲突、算法运行时不兼容、检查点损坏、构件校验失败和持久化失败。

错误响应不能附带未揭示行情。可恢复失败保留原状态并提供重试；不可继续计算的版本问题保留历史回看入口。

## 14. 性能、可靠性与可观测性

### 14.1 性能目标及定标要求

以下为工程设计目标，尚未经过训练实现测量，不作为现有能力描述：

| 场景 | 初始目标 |
| --- | --- |
| 不超过 3000 根已知 K 线的初始化 | 本地环境端到端 P95 不超过 2 秒 |
| 常规单根推进，图表显示窗口约 300 根 | 本地环境端到端 P95 不超过 300 ms |
| 历史一步恢复 | 本地环境端到端 P95 不超过 500 ms |
| 需要扩大重算或完整兜底的步骤 | 可超过常规目标，但须有忙碌提示、准确结果和独立统计 |

实施前必须固化验收机器配置、运行方式、数据规模、样本、采样次数与计时口径。若基准证明初始数值不合理，应形成明确评审记录并更新需求版本，不能在报告中默默降低标准。

至少测试 500、1000、3000 根日线级输入及 10000 根分钟级输入；长序列初始化单独定标。常规路径和兜底路径分组报告，同时报告总体延迟，不能通过排除所有慢步骤美化结果。

按两种计算策略分别取样；日线创建和追加的资格验证、快照复制耗时计入对应端到端指标。首版周月性能测量不包含日线辅助源，因为该功能不在本版范围内。

### 14.2 性能实现约束

- 同一快照中不随每次推进重新读取、复制和散列全部原始行情；可以使用前缀版本与内容块索引。
- 指标与结构计算、结果存储和图表渲染分别测量，定位瓶颈。
- 初始化允许批量计算，但不能为快进体验预先向前端下发未来构件。
- 连续推进时，内存不能保留每一步完整状态导致无界增长。
- 训练计算不得阻塞默认模式的主要读取交互；并发和任务调度机制在详细设计中明确。
- 为长运行提供进度或忙碌状态，不通过跳步、丢事件或改变规则降低耗时。

### 14.3 最低诊断信息

保存操作类型、会话与轮次、前后游标、计算策略与版本、资格/连续性版本、结果哈希、输入新增根数、重算起点、受影响对象数、计算/落库/响应耗时、兜底次数与原因、校验失败和冲突信息。

面向用户的“本步变化”只显示有助于理解结构的信息，不堆砌内部缓存、数据库或调度细节。内部诊断也不得经当前步骤响应暴露未来数据。

| AC-31 | 策略固定与空集合 | 5/30/d=full，w/m=pen_centers_only；请求或恢复不得任意切换。周月最高原生 L1、走势/点/关系为空，内部回试证据可保留，普通指标仍可显示 |
| AC-32 | 首版无日线参考 | 周月训练不读取参考日线 run、不计算或返回 daily_l2；按钮、计数、来源提示、详情、浏览器状态和旧默认缓存均无参考对象，默认模式投影正常保留 |
| AC-33 | 缓存不自动转正 | 日线盘中缓存经过收盘、跨日、重启仍不因时间推进而可训练；旧价格恢复不能复活失效证明 |
| AC-34 | 当日请求与内容资格 | 收盘确认边界前发起而边界后返回的请求不满足新确认；失败、被拒收来源或与实际入库内容不匹配的响应不能让缓存获得资格 |
| AC-35 | 证明与来源变更 | 价格、量额、复权、来源修订等任一受哈希约束字段变化后按现规则失效；创建/追加只接受资格一致的内容，不按价格相同放行 |
| AC-36 | 历史证明与训练时钟 | 一次性历史基线及合法新历史导入可以冻结；证明登记时间晚于历史游标不导致合法旧 K 线被排除，也不回写构件确认时间 |
| AC-37 | 一致性冻结与旧会话 | 并发行情/证明/日历更新不产生混合版本快照；默认库后续修订或来源失败不改写旧训练，未合格新增行不能追加 |
| AC-38 | 无价格变化的资格变化 | 新获资格或资格失效即使价格不变也正确更新创建可用范围与追加检查；已创建轮次终点仍需用户主动追加才延长 |

### 15.5 样本与实际浏览器要求

- 使用可控合成样本与真实股票样本，覆盖五个支持周期；不能只用固定笔数组代替原始 K 线回放。
- 小型边界样本执行逐根穷举对照，真实样本覆盖完整测试区间及关键结构事件附近的每个前缀。
- `full` 中 L3 及以上如缺乏真实样本，必须以可验证合成样本覆盖并明确披露真实覆盖不足，不能写成全部真实场景通过；不要求周月构造被策略禁止的 L3 样本。
- 实际浏览器验证快捷键、长按、输入焦点、绘图拖动、缩放、选中详情、分页、模式切换、多标签页冲突及刷新恢复。
- 检查网络响应和前端状态中没有未揭示行情；图上看不见不等于没有提前下发。
- 验证周线三笔核心显示/命中与月线完整范围显示的现有区别；恢复旧步骤后使用当时构件的对应核心和完整证据，不把周线显示裁剪错误应用到月线或引擎输入。
- 回归默认模式周月日线参考开关和选择；切入训练后确认没有参考残留，切回默认后仍按默认上下文正常工作。
- 自动化测试、构建成功、接口校验与浏览器验收分别报告；不能互相替代。

## 16. 建议实施顺序与交付边界

以下用于说明可行实施路径，不等于本轮已授权开始业务实现，也不替代后续详细实施计划。

1. **固化现有行为**：记录 v27 周期策略、正式日线资格、现有展示规则与基线样本，完善原始 K 线前缀对照，澄清连续区间及两种时钟契约。
2. **整理共同计算入口**：隔离行情获取和存储副作用，保留按周期策略分流及默认参考层，建立同资格同策略的批量对照通道。
3. **建立训练数据域**：实现独立训练库、行情与证明一致性冻结、不可变快照、会话与轮次、步骤和幂等命令。
4. **实现增量与恢复**：处理未决包含、笔修订、依赖失效、指标状态、检查点及完整计算兜底，并逐步通过对照。
5. **完成训练交互**：先以日线 full 和周线 pen_centers_only 分别跑通创建、单步、变化、回退、笔记、保存恢复和固定终点追加；训练不接入日线参考层。
6. **覆盖其余周期与边界**：完成分钟虚拟时钟、真实缺口、月线完成状态及全周期验收。
7. **回归与性能验收**：证明隔离、默认模式兼容和实际浏览器行为，完成性能定标及长时间运行检查。

只完成逐根完整重算原型，可以用于验证时点语义和界面联调，但不能据此宣布本需求完成。五个周期各自的规定能力、正式输入资格、增量约束、隔离、回退恢复和主动追加均属于首版完整交付范围；日线辅助参考源不属于首版训练交付。

最终实现交付至少包含：代码与迁移说明、接口契约、默认与训练行为对照报告、逐根一致性报告、隔离/故障测试记录、性能报告、浏览器验收记录，以及明确的未覆盖样本与限制。

## 17. 假设、实施前定标项与变更管理

### 17.1 首版假设

- 应用仍为当前本地工作台，面向单用户使用，不新增账号体系和外部共享权限模型。
- 使用现有本地行情和交易日历能力，不采购或替换行情源。
- 默认模式后台同步继续工作；训练通过冻结数据和独立存储保持稳定。
- 本文绑定的 v27 规则及周期策略为本次算法基线，不能在训练迭代中顺带重新解释中枢、笔或买卖点，也不能随运行版本变化自动改变旧会话策略。
- `full` 结构训练保留当前周期内递归模型，不将 L2/L3 映射成其他行情周期；周月仅保留原生笔及 L1 参考计算。
- 首版训练与默认周月图允许存在已确认的参考层差异：训练不含日线 L2，默认模式继续提供。未来如引入训练参考源，须另行定义共同 as_of、双输入快照和联合恢复，不能直接启用默认最新快照。

### 17.2 详细设计必须确定的工程参数

以下不改变已确定产品范围，但必须在编码与验收前形成记录：
