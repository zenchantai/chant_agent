## 结论

v30 已在隔离数据库完成实现、十项重算、结构/API 审计、逐笔前缀重放和浏览器验收。L1 到 L2 不再要求预先存在三个全局 `MovementRevision`，而是直接从连续确认笔构造规范 `SegmentProof`；L3 以上的递归边界保持不变。

## 实现结果

### 证明与层级

- L1 到 L2 的局部证明直接从确认笔构造，三段均至少三笔、连续、方向交替、各自具有严格三笔重叠见证，且三段具有严格正宽度共同重叠。
- `SegmentProof` 使用稳定 family/revision ID；动态延长和固定均以追加修订表达，不覆盖旧状态。
- 全局走势仍可适配为 `SegmentProof(source_kind=movement)`，但不再是 L1 到 L2 的准入条件。
- 动态父中枢使用 `unit_kind=segment_proof`，`fixed_zd/fixed_zg=null`，不可递归。
- 固定父中枢保持前三段核心，写入 `promotion_confirmed_at` 后才可参与本级后续走势计算。
- 父中枢使用独立家族；低级中枢保持活动和可追溯，不因升级被停用。
- 周线和月线继续执行 `pen_centers_only`，不生成候选、段证明、走势或点位。

### 契约、持久化与页面

- `structure` 已增加 `promotion_candidates`、`promotion_candidate_revisions`、`segment_proofs` 和 `segment_proof_revisions`。
- 新增只追加表 `chan_promotion_candidates` 和 `chan_segment_proofs`；旧运行不迁移、不重写。
- 普通接口返回当前候选和选中段；`diagnostics=true` 返回完整候选修订、段修订和未选规范证明。
- 页面区分延伸候选、扩展未解、动态父中枢和固定父中枢；选中父中枢后按 S1/S2/S3 高亮底层笔。
- 动态父中枢使用虚线，固定父中枢使用实线；周/月显示日线 L2 参考而不创建本周期原生 L2。
- `/api/health` 与快照元数据共用配置，当前输出：

```text
movement_partition_mode = canonical_boundary_stream
promotion_segment_mode = pen_native_segment_proof
center_promotion_mode = unified_segment_proof
nine_unit_mode = owned_units_from_core
```

## 本轮额外修复

第一轮 v30 实现后，前缀回放暴露了两个会破坏只追加和反未来约束的问题，本轮已修复并加入回归测试：

1. 同一 `SegmentProof` revision ID 曾可能在后续观察时点对应不同底层笔。现在 `_normalize_segment_proof_revisions()` 按首次观察顺序生成修订；同一 ID 若再次出现但语义不同会直接报错。
2. 扩展候选曾可能使用后续数据回写 `required_unit_ids`，父中枢也可能早于候选观察时间形成。现在扩展候选冻结首次观察范围，候选和父中枢时间统一取证明可用时间与候选观察时间的较晚者。

同时补齐确认结构点直接固定 S3，以及 S1/S2 只能由下一段前三笔证明结束的规则。
