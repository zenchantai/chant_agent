## 1. 目标与范围

保留“当前周期确认笔作为最低完成走势单位”的简化，把中枢形成类型落实到起算与归属规则中：

- 向上发展过程中的回调中枢，以向下笔作为 A，核心为下—上—下。
- 向下发展过程中的回升中枢，以向上笔作为 A，核心为上—下—上。
- 原点处尚未确定方向的重叠结构有独立状态，不能套用常规进入段规则，也不能冒充方向已经确定的结构。
- 核心形成后，按固定形成方向维护 Z 序列，分别处理延伸、离开、回试、破坏、新生和扩展。
- 高级中枢需要可追溯的三段低级走势构成证明，不能直接把两个波动包络的交集当作完整定义。

本次不改标准笔、分型和包含处理，不恢复线段引擎，不把日线 L2 映射为周线级别，不新增交易执行功能，不顺带重写所有背驰及一、二类买卖点规则。

保留 v27 周期策略：5 分钟、30 分钟、日线使用完整模式；周线、月线仅计算原生 L1 笔中枢及状态，日线 L2 仍为独立投影。保留按级别展示活动中枢和组成中枢、买卖点精确引用历史修订的现有能力。

## 4. 拟采用的领域模型

### 4.1 三种方向分别保存

| 字段 | 含义 | 不能被当作什么 |
| --- | --- | --- |
| `process_direction` | 当前结构工作区的有证据过程方向，up/down/unknown | 已完成上涨／下跌趋势 |
| `formation_type` / `z_direction` | pullback/down 或 rebound/up；未定型时 undetermined | 整个走势最终方向 |
| `movement.direction` / `classification` | 已有走势规则判定的过程方向及盘整／趋势分类 | 任意单根笔的方向 |

`entry_direction` 继续保留，含义仅为进入路径首尾的净方向。禁止单独通过 `entry_direction != z_direction` 判断理论合规。

### 4.2 `DirectionContext`：中枢之前的上下文

建议新增上下文记录，至少包含：

```text
id, level, source_timeframe, continuous_range_id
anchor_date, anchor_price, anchor_kind
process_direction: up | down | unknown
evidence_status: provisional | established
source_unit_ids, source_event_ids
established_at, input_cutoff, invalidated_reason
```

`anchor_kind` 区分：

- `confirmed_boundary`：已有独立完成证据的走势边界。
- `verified_origin`：有来源证明的真实起点，或明确指定的教材／测试原点。
- `model_origin`：固定完整输入基线的首个有效端点，属于工程起点，不声称是市场真实历史原点。
- `truncated_left`：缺少左侧上下文，不能冒充前三者。

同一原生周期分别维护上下文，不从日线 L2 投影反向决定周线原生中枢。

### 4.3 中枢形成阶段与生命周期分离

形成阶段使用：

```text
origin_overlap       原点初始重叠结构，尚未完成方向性分组
directional          方向性核心已经成立
boundary_candidate   左侧上下文不足
```

生命周期另行表示形成、延伸、离开、回试、破坏、结束和升级。不能用单个 `status` 同时表示“没有方向”“已经离开”和“已经升级”。

`origin_overlap` 可以作为原点中枢显示，但必须标注“原点／方向待定”，不得生成正式同级买卖点或作为已完成走势递归输入。

### 4.4 家族、修订和归属

- 正式核心形成后，同一方向性阶段内的核心和 `ZD/ZG` 固定。
- 原点初始结构转为方向性核心，通过 `origin_normalized` 事件增加修订，不原地修改旧修订。
- 家族身份由稳定工作区锚点与形成事件确定，不能仅依赖可能改变的第一根核心笔。
- 同一分解视角、同一级别、同一时刻的活动核心不能重复拥有整笔；相邻结构可共享端点。
- 父级引用低级组成证据属于层级引用，不属于两个并列中枢重复拥有。
- 进入、离开和连接的上下文引用可共享，但要与核心／延伸的计算归属分开。
- 历史修订和当时引用它的点位完整保留；规范化不能把新证据回填为旧时刻已知。

## 5. 方向建立与核心起算

以下是本方案最需要评审的业务规则。全部先落为合成用例和逐笔回放，再实现主引擎。

### 5.1 不等待完整趋势才确定上下文

中枢用于判定走势，不能反过来要求先完成一条趋势才能寻找中枢。

`process_direction` 描述当前已知发展过程。它允许早于 `movement.classification` 确定，但必须提供可独立验证的锚点和证据。

建议的证据优先次序：

1. 独立确认的走势边界，以及边界后首个已完成方向单位，可建立新工作区的过程方向。
2. 旧中枢发生完整离开与首次完整反向回试，确认有效破坏后，可建立后继方向上下文；这不自动确认旧走势结束。
3. 原点初始化按下节的生长条件建立方向。
4. 仅有进入路径的净涨跌、最后一笔方向或价格暂时创新高／低，均不足以独立替代上述证据。

若这些依据指向不同分解解释，保留候选及冲突原因，不以扫描顺序替用户决定解释。候选不进入正式递归。

### 5.2 原点 0→5 的建议工程判据

在明确的原点工作区中，首先允许前三个已完成单位形成 `origin_overlap`。此时只承认重叠结构，不把它定为整个过程的方向性中枢。

针对教材第 16 页，建议以如下最小充分条件建立向上过程上下文并完成规范化：

```text
连续五个已完成单位：上、下、上、下、上
端点：P0、P1、P2、P3、P4、P5

P5 > max(P1, P3)
min(P2, P4) > P0
P1→P2、P2→P3、P3→P4 存在正宽度交集
```

对称得到向下条件：方向下、上、下、上、下，`P5 < min(P1,P3)`，`max(P2,P4) < P0`，且 P1–P4 有正宽度交集。

这里“五单位＋极值关系”是对教材示例的明确工程解释，不是声称教材给出了该通用定理。它只证明本模型的过程上下文，不证明一个趋势已经完成，也不保证后续继续同向。

满足条件时：

- 选择 P1–P4 方向性核心，原点到 P1 为进入上下文。
- `formed_at` 可记录核心三单位齐备时间；`direction_established_at` 和该正式修订的 `available_at` 不早于第五单位完成时间。
- 保存原来的 P0–P3 修订及其可见时间。
- 前缀回放到 P3 时不能看到 P5 才确认的方向性核心。

未满足条件时，继续维护原点候选及其来源，不强行改用相反方向窗口。复杂起步形态通过完整离开回试或后续有效边界建立上下文，不能只因为“已经五笔”就定方向。

### 5.3 数据左边界不等于原点

- 图表分页只展示已有结构快照，不能将当前视窗最左端重新当作模型起点。
- 正式计算使用固定的完整数据范围或有效检查点。`model_origin` 与输入基线、覆盖范围一起保存，并明确是工程选择。
- 数据补齐更早历史后，建立新输入版本和新运行，不能悄悄沿用旧原点家族身份。
- 单独截取的测试／导入片段，没有原点证明或上游检查点时，输出 `boundary_candidate`。
- 缺口和数据断点重置连续上下文，禁止跨断点拼接核心。

### 5.4 有方向上下文后的选核

向上过程只考虑下—上—下的核心，向下过程只考虑上—下—上的核心。三个单位必须完成、连续、交替，且存在正宽度交集。

工作区内按时间寻找最早满足上述全部条件的核心：

- 前一组三单位交集失败时，只推进到同一预期 A 方向的下一个合法起点。
- 不允许为了尽早画出矩形，转而接受相反形成类型。
- 选核前的路径保存为 `pre_core_path`；只有满足组件定义时才同时导出为进入组件。不得为了保留旧字段，将所有跳过的笔强称为完整单向进入走势。
- 路径中已经形成其他合法中枢、遇到有效破坏或边界事件时，先处理事件，不继续吞并成进入路径。
- 当前中枢尚未结束时，新窗口先进入其生命周期判断，不能并列提交另一个核心。

原例 `1→5→3→10→7→15→13`，在已经建立向上上下文的前提下，不再采用 `3→10→7→15` 的上—下—上作为该向上过程的回调枢。两个向下起算窗口均无交集时，允许“尚未形成方向性中枢”，不能为维持旧数量而放宽规则。

没有向上上下文的同一段裸价格，结论可能仍是原点或边界候选。测试必须提供锚点类型和截至时刻，不能只用价格数组省略语义前提。

## 6. 核心、Z 序列与价格边界

### 6.1 核心计算

对于合格核心 A、B、C：

```text
Z1 = A
Z2 = C
ZD = max(low(A), low(C))
ZG = min(high(A), high(C))
```

同时检查它与三单位交集一致；不一致说明单位范围或衔接语义异常，应生成审计错误。

### 6.2 Z 指标

只有属于该中枢、与形成方向相同的已接纳单位进入 Z 序列：

```text
GG = max(g_n)       所有已接纳 Z 的最高点
G  = min(g_n)       所有已接纳 Z 的高点最小值
D  = max(d_n)       所有已接纳 Z 的低点最大值
DD = min(d_n)       所有已接纳 Z 的最低点
```

`ZD/ZG` 由初始 Z1、Z2 固定，不能用后续 `D/G` 不断收窄核心。进入路径、未返回的离开路径和不属于 Z 的连接单位不混入上述指标。

`context_low/high` 继续表示较广的上下文包络，但不能冒充中枢核心或正式 Z 包络。

### 6.3 相等边界的建议口径

教材不同页的“触及”“不跌破”“不返回”文字有边界解释空间。本版建议保留项目的保守处理，但明确为工程约定：

- 正式核心和正式扩展核心必须有正宽度交集。
- Z 与核心有正宽度交集：可作为延伸证据。
- 仅触及边界：记录 `touch`，不作为新增 Z 的正宽度重叠证明，也不作为破坏证明。
- 回试低点严格高于 ZG 才确认向上破坏；回试高点严格低于 ZD 才确认向下破坏。
- 等于边界时保持未破坏，并保留首次回试的身份；不得把后续有利回试偷换成“第一次回试”。

初始工程容差沿用 `1e-9`，统一经价格比较函数使用；是否改为最小报价单位须另行论证，不在本次隐式改变。

## 7. 中枢生命周期与事件顺序

| 当前阶段 | 新证据 | 处理 |
| --- | --- | --- |
| 原点重叠 | 方向生长条件成立 | 追加方向性修订，保留历史原点修订 |
| 方向性核心 | 同向 Z 与核心重叠 | 延伸，核心固定，更新 Z 指标 |
| 方向性核心／延伸 | 反向连接或暂时离开 | 保存连接／离开证据，不立即关闭 |
| 离开待定 | 首次完整回试返回核心 | 本次离开失败，按归属规则接回原中枢 |
| 离开待定 | 首次完整回试仅触及边界 | `touch`，保持未破坏，不发正式三类点 |
| 离开待定 | 首次完整回试严格不返回 | 确认中枢有效破坏，记录方向和时间 |
| 已破坏 | 后续形成合法方向性核心 | 判断同级新生／扩展候选／边界冲突 |
| 扩展候选 | 三段构成证明完整 | 提交正式父级修订 |
| 任意未完成状态 | 数据结束／缺口 | 截断或保持候选，不伪造完成 |

具体原则：

1. 每次只消费当前已确认单位及其截至时刻可用证据。
2. L1 的一根确认笔即最低完成单位。首次离开与反向回试不能任意聚合多笔后挑选有利结果。高级别消费对应已完成低级走势；更低级连接组件可以保留，但不能冒充同级单位。
3. 中枢破坏方向可以与原过程方向相反。三卖出现在向上过程中是允许的，不能为了维持方向标签而忽略。
4. 中枢破坏不自动等于整个走势结束。已有一类点、盘整转折及边界完整性规则仍须分别满足。
5. 新形成方向的工作区可以先候选推进；若旧走势边界尚未确定，不能先把它提交为已完成反向走势。
6. 同一批单位先更新旧中枢状态，再产生后继工作区，再评估新核心和级别关系。禁止先全局生成所有核心，再事后任意分配给走势。

为避免循环确认，事件须形成有向无环的证据依赖：确认单位 → 中枢／离开回试证据 → 结构转折与边界证据 → 完成低级走势 → 正式高级中枢。高级中枢本身不得成为其三段子走势完成的唯一理由。

## 8. 扩展与高级递归

### 8.1 包络关系只启动候选

保留两中枢核心和 Z 包络的关系检查。核心分离而波动范围重叠，可以产生 `expansion_candidate`，用于提示可能形成高级结构。

候选保存低级中枢修订、连接组件、重叠 Z 证据、可能的分组、缺失证据和首次可见时间。此时不隐藏低级活动中枢，不升级活动走势，不向上递归。

### 8.2 正式父中枢统一使用三段构成证明

正式 L(k+1) 中枢必须提交连续三段 Lk 走势 U1、U2、U3：

- 身份和级别明确，有各自合法中枢或已验证的级别构成依据。
- 各自完成证据独立可追溯，方向交替，源区间连续。
- 在同一构成证明中不重复拥有整笔或完整低级走势，只共享合法端点。
- 三段价格范围有正宽度交集。
- 有高级方向上下文时，仍执行回调／回升起算；原点情况仍执行初始化规则。

正式核心采用 `max(U1.low,U2.low,U3.low)` 与 `min(U1.high,U2.high,U3.high)`。保留 `child_movement_ids`、具体边界证明和共同交集。

这里的三段构成证明不等于新增一套用户可见的全局同级别分解功能。内部可以保存专门的 `decomposition_proof`，但它必须真实引用可验证的低级走势，不能为得到父核心临时拼出三个无完成证据的区间。

### 8.3 教材动态扩展与正式确认的区分

教材第 23 页允许扩展中的第三段尚未完成，区间随之变化。本方案建议：

- 前两段完成、第三段未完成时，展示扩展候选和候选区间。
- 第三段完成后，才将该构成证明提交为正式父中枢，并允许递归。
- 候选变化保留证据时间，不回写历史正式核心。

这是保守的工程确认策略，可能比教材的动态扩展判断更晚产生正式 L2/L3。延迟必须在对比报告中量化，不能描述成与教材所有当下判断完全一致。

如果某种延伸形态只有依赖父级成立才能确认子走势，而缺少独立完成依据，必须保留候选并报告 `circular_completion_dependency`。不得为了凑齐三段而循环确认。此类代表图在阶段一验证，不能留到发布时才发现无法构造。

### 8.4 九段不是升级开关

- 在笔为底层、三段子走势各至少三笔且不共享整笔的模型中，三段证明自然产生至少九笔的数量下界。
- 计数范围是构成证明中的源单位，不能靠前置进入笔补足。
- 满九笔而不能给出三段结构证明时不升级。
- 任意更长的普通延伸也不能仅凭长度升级。
- 延伸路径和相邻中枢重叠路径最终提交相同的构成证明；禁止继续保留可绕过三段证明的包络升级旁路。

旧 fixture 的前缀 `1→10→6→15→8→20→12→25→21→30`，全输入九笔，其中进入笔不属于父构成区间，现版可在八笔组成范围上产生 L2。新版本应先保留扩展候选，直到具体构成证明齐备。不能把新预期简化为“再多来一笔就自动升级”。

## 12. 分阶段实施与交付

### 阶段一：规则定稿与教材用例

1. 评审第 5、6、8 节的工程约定，形成正式后继需求和教材页码对照。
2. 将第 16 页生长过程、第 19 页延伸、第 24—25 页扩展和第 31—32 页代表图转为标注清楚的合成输入；原图无价格时使用保持相对高低关系的数值，注明是工程化例子。
3. 每个用例记录逐前缀预期：当前已知方向、核心起点、Z 成员、归属、状态、确认时间和缺失证据。
4. 先验证方向建立、复杂初始化及扩展完成依赖能够自洽；有理论冲突时修订完整方案，不靠测试迁就实现。

交付：正式规则、来源矩阵、可评审例图和预期表。此阶段不切换生产规则。

### 阶段二：方向性 L1 与原点状态机

实现方向上下文、原点／截断区别、核心选择、规范化修订、Z 指标和离开回试。用固定输入进行纯函数重放，并与旧引擎逐项对照。

周月策略也使用相同 L1 规则，但仍不输出走势和买卖点。

交付：L1 内核及审计；所有方向差异均可追溯到上下文证据。

### 阶段三：扩展构成与递归

将包络升级改为候选路径，实现三段构成证明、动态第三段候选和正式父核心，联通已有走势完成规则，排除循环依赖。

交付：L2+ 内核、组成关系和候选原因。不能通过减少正式 L2 数量掩盖构成器未实现；每个受影响案例须说明是合理延后、规则变化还是能力缺失。

### 阶段四：API、持久化与图表

完成新修订字段、引用闭包、旧运行兼容、标签和证据交互。保留组成中枢显示与日线投影。

交付：端到端隔离运行与可操作页面，不接管当前活动运行。

### 阶段五：历史对照、验收与切换

使用同一冻结行情基线计算旧版与新版，完成全部矩阵审计、自动化测试和真实浏览器验收。提供差异报告与回滚演练结果后，再按已获得的实施／上线授权范围进行原子切换。

本方案的编写请求本身不包含阶段二至五的执行授权。

### 13.2 审计不变量

- 回调枢 A/C 向下，回升枢 A/C 向上；类型与方向上下文相符。
- 三笔完成性、连续性、正宽度交集和 A/C 交集等价均成立。
- 正式方向性核心固定；普通延伸不会改变核心。
- 活动同级归属不重复，父子层级引用和上下文引用分开。
- 所有确认和修订只引用当时已可用的证据。
- 正式父中枢必须有三段构成证明；证据依赖无环。
- 点位使用当时的确切中枢修订，不跳转到家族最新高级修订替代。
- 旧版、新版与预览运行隔离；截断不能成为完成事件。

- 读取实施当时全部启用标的，遍历支持的 5/30/d/w/m 周期，不写死历史“10 项”数量。

- 实际点击中枢与买卖点，验证 A/B/C、Z、进入、离开回试与历史修订高亮。

## 14. 数据迁移、切换与回滚

1. 先记录当前分支、工作区、服务监听、活动运行、版本、指纹、启用标的和数据截止时间，保留无关工作。
