# 笔中枢延伸与扩展的统一升级模型实施方案

## 1. 背景与问题

当前工程采用简化笔中枢模型：在最低计算层，当前周期确认笔代替当前走势的次级别走势单位。三个连续、方向交替且存在严格共同重叠的笔形成一级中枢，后续符合规则的笔形成中枢延伸。

现有 v28 实现对高级中枢存在两套不完全一致的路径：

- 两个同级中枢发生扩展时，扩展接触、连续性和见证区间主要由底层笔证明；
- 扩展关系升级为高级中枢时，优先要求已经存在的全局 `movement`，或再通过局部边界和中枢证据构造三段；
- 单个中枢内部延伸达到九笔以上时，没有与扩展路径等价的高级构造入口。

这会导致同一批笔在“扩展关系”中可以作为次级别证据，在“高级中枢定界”中却可能因缺少预先生成的全局走势而被拒绝；也会导致长时间延伸的中枢无法进入升级检查。上证指数日线中枢 `#12`（`2020-07-09` 至 `2021-05-11`）是当前明确样本：活动快照内该中枢拥有 19 笔，其中 3 笔核心、8 笔延伸、8 笔交替外围笔，但仍仅保留为 L1。

本方案统一延伸升级与扩展升级的构造公理、证明器、时间语义和审计方式，消除两条路径的层级单位矛盾。

## 2. 目标

1. 正式确认最低层简化：`笔 = L0 次级别走势单位`。
2. 为每一级定义统一的原子单位和递归关系，不允许同一级在不同路径中切换单位口径。
3. 单中枢九笔以上延伸和两个同级中枢扩展，只作为不同的候选来源，最终调用同一个高级中枢构造证明器。
4. 九笔达到后必须检查高级构造，但不得把“数量达到九笔”直接等同于升级成功。
5. 同时支持第三段未完成时的动态高级中枢和第三段确认后的固定高级中枢。
6. 保留不可变修订、证据可追溯、无未来函数、连续性和单位唯一归属。
7. 用上证指数日线 `#12` 固化真实行情回归结论，并覆盖扩展、反例和更高级递归。

## 3. 非目标

- 不改变确认笔算法、包含处理、分型或标准笔规则。
- 不在本次顺带修改三类买卖点、背驰或交易训练规则。
- 不以日期、证券代码或页面编号写行情特判。
- 不把任意九根 K 线、九个拐点或九个非连续单位当作九笔。
- 不重写旧运行；旧快照保留为历史证据，新规则使用新定义版本重算。
- 不把动态高级中枢当作已完成走势继续递归。

## 4. 统一术语与层级公理

### 4.1 原子单位

定义 `U(L)` 为构造 L 级结构时使用的直接次级单位：

- `U(1) = 已确认笔`；这是本项目的最低层简化约定。
- `U(L) = 已确认且可递归的 L-1 级走势段`，其中 `L > 1`。

每个原子单位必须至少具有：

- 唯一 ID；
- 级别；
- 方向；
- 起止日期与起止价格；
- 价格区间 `[low, high]`；
- 确认时间；
- 连续范围、序列和原始笔来源。

### 4.2 中枢核心

连续三个原子单位 `A/B/C` 可以构成 L 级中枢核心，当且仅当：

1. 三者属于同一连续序列；
2. 时间和端点价格连续；
3. 方向满足 `A == C != B`；
4. 三个单位均达到该状态要求；
5. 存在严格正宽度共同重叠：

```text
ZD = max(A.low, B.low, C.low)
ZG = min(A.high, B.high, C.high)
ZD < ZG
```

触边相等不构成新生中枢核心；容差沿用工程统一的 `EPSILON`。

### 4.3 延伸

中枢形成后，后续同向 Z 单位继续与固定核心 `[ZD, ZG]` 相交时，属于同一中枢家族的延伸。普通延伸不得改写固定核心，只追加不可变修订和 Z 波动证据。

延伸长度达到九个连续原子单位后，系统必须生成“高级构造候选”，但是否升级由统一证明器决定。

### 4.4 走势段

本方案中的“走势段”是高级中枢构造证明中的连续单位组，不等于必须预先存在的全局 `movement` 数据库对象。

一个走势段必须：

- 至少包含三个连续 `U(L)`；
- 方向可由首尾端点和内部方向规则确定；
- 含有可证明其为 L 级走势的中枢证据；
- 有明确起止边界、完成状态和可用时间；
- 不与同一证明中的其他走势段重复拥有单位。

全局 `movement` 可以作为走势段证明来源，但不是唯一来源。局部构造产生的走势段证明与全局对象使用同一字段、同一校验规则，不再使用不同的几何口径。

### 4.5 高一级中枢

三个连续 L 级走势段 `S1/S2/S3` 构成 L+1 级中枢，当且仅当：

1. `S1.direction == S3.direction != S2.direction`；
2. 三段首尾连续；
3. 每段拥有独立、合法的 L 级证明；
4. 三段的源单位互不重复；
5. 三段区间存在严格共同重叠：

```text
parent_ZD = max(S1.low, S2.low, S3.low)
parent_ZG = min(S1.high, S2.high, S3.high)
parent_ZD < parent_ZG
```

不能用 `S1/S2` 重叠且 `S2/S3` 重叠替代三段共同重叠。

## 5. 两种候选来源、一个证明器

### 5.1 延伸候选

当一个 L 级中枢家族的连续拥有单位达到九个时，从该家族首个核心单位开始，按时间顺序向后搜索所有合法的三段划分。

要求：

- 进入单位不得用于补足九个单位；
- 离开和回试单位只有在仍属于该候选连续范围时才能使用；
- 候选范围不能跨越序列断裂、数据缺口或已确认的结构边界；
- 不要求机械固定为第 `1-3/4-6/7-9` 个单位；允许合法边界使每段超过三单位，但每段至少三单位；
- 优先选择最早在当时信息下可确认、且不产生单位冲突的证明。

候选来源标记为 `extension_decomposition`。

### 5.2 扩展候选

两个同级中枢核心分离，但 Z 波动范围发生教材定义的扩展接触时，先独立确认扩展关系。扩展关系只说明需要在两个中枢及连接单位组成的连续范围中检查高级构造，不直接给出高级中枢几何。

将以下范围交给同一个证明器：

- 前中枢实际拥有单位；
- 两中枢之间的连接单位；
- 后中枢截至当前时点实际拥有单位。

候选来源标记为 `expansion_decomposition`。

扩展关系可以已经确认，而高级区间仍因三段证明不足保持 `unresolved`。二者状态不得混为一体。

### 5.3 统一证明函数

新增单一职责接口，名称可在实现时按现有模块风格调整：

```python
build_parent_center_proofs(
    *,
    child_level: int,
    units: list[StructureUnit],
    child_centers: list[CenterRevision],
    boundary_events: list[PointRevision],
    global_movements: list[MovementRevision],
    required_unit_ids: set[str],
    candidate_source: Literal[
        "extension_decomposition",
        "expansion_decomposition",
    ],
    observed_at: str,
) -> list[ParentCenterProof]
```

该函数统一完成：

1. 连续范围规范化；
2. 合法走势段边界枚举；
3. 全局与局部走势证据适配；
4. 方向、连续性、级别和单位归属校验；
5. 三段共同重叠计算；
6. 动态与固定状态判定；
7. 最早可用时间计算；
8. 确定性排序和候选去重。

`decomposition_proofs()` 与 `internal_decomposition_proofs()` 不再作为两套含义不同的最终判据。可以保留为内部适配器，但输出必须先规范化，再进入同一个验证与排序流程。

## 6. 边界、确认与时间语义

### 6.1 前两段

`S1` 和 `S2` 必须有独立确认的反转边界。确认可以来自：

- 已确认全局走势的终点；
- 当前层级规则认可的独立结构点；
- 与全局走势同等严格的局部边界证书。

不能因为后续出现了高级中枢，反向循环证明此前边界成立。

### 6.2 第三段

- `S3` 已开始、已有至少三个原子单位并能确定共同重叠，但尚未确认结束时，允许生成 `dynamic` 高级中枢修订。
- `S3` 出现独立确认边界后，生成 `fixed` 修订。
- `dynamic` 可以显示、审计和参与当级观察，但 `recursive_eligible=false`。
- `fixed` 在完整审计通过后才允许作为更高一级构造输入。

### 6.3 防未来函数

每份证明必须保存：

- `observed_at`：本次前缀计算的观察时点；
- `evidence_available_at`：所有必要证据中最晚的可用时间；
- 各段边界的独立确认时间；
- 动态转固定的确认时间；
- 父中枢首次形成时间与每次修订时间。

在任意历史前缀重放中，不得引用 `observed_at` 之后的单位、修订、点位或全局走势状态。后续数据不能回写早期修订的核心、边界或确认时间。

## 7. 候选选择与冲突处理

同一连续单位流可能产生多个合法三段划分。采用以下确定性顺序：

1. `evidence_available_at` 最早；
2. 起点最早；
3. 第一个边界最早；
4. 第二个边界最早；
5. 使用单位数量较少；
6. 稳定 ID 字典序。

一旦某一父中枢家族取得单位所有权：

- 同一分解视角下，其他活动父中枢不得重复拥有这些单位；
- 历史修订可以引用旧证据，但不能作为并列活动结构重复消费；
- 不同级别允许通过 `source_pen_ids` 建立祖先追溯，不视为同级重复归属；
- 延伸候选和扩展候选若得到相同的三段与核心，应合并为同一父家族，并在 `formation_modes` 中同时记录两种来源；
- 两种来源若形成不同合法候选，按上述确定性顺序选主候选，其他候选作为诊断证据保留，不静默丢弃。

## 8. 中枢生命周期

统一后的父中枢状态至少包括：

- `candidate`：达到检查门槛，但三段证明未齐；
- `dynamic`：三段共同重叠已成立，第三段尚未独立完成；
- `formed`：第三段完成，核心固定；
- `extended`：后续单位继续返回固定核心；
- `broken`：离开并按现行规则完成破坏确认；
- `absorbed`：作为同一父家族修订或更高级扩展组成被吸收。

状态变化追加修订，不覆盖历史记录。普通延伸不改写 `fixed_zd/fixed_zg`；动态第三段导致的区间变化使用独立修订，固定后不可被未来数据改写。

## 9. 数据模型与证据字段

优先沿用现有不可变修订表和 JSON 证据，避免对旧运行做破坏性迁移。新运行中的父中枢应至少记录：

- `level`、`family_id`、`revision_no`；
- `formation_modes`；
- `candidate_source_ids`；
- `boundary_status`；
- `decomposition_proof`；
- `child_level`、`child_unit_kind`；
- 三个 `segments` 的方向、起止、区间、状态和确认时间；
- 每段的 `source_unit_ids`、`source_pen_ids`；
- 每段的 `level_evidence_ids`、`completion_evidence_id`；
- `owned_unit_ids`、`context_unit_ids`；
- `ZD/ZG`、`fixed_zd/fixed_zg`；
- `formed_at`、`promotion_confirmed_at`、`revision_at`；
- `missing_evidence` 和未选候选诊断。

关系对象继续负责表达扩展接触，不承担尚未定界的高级中枢几何。建议补充：

- `promotion_candidate_status`；
- `promotion_proof_ids`；
- `boundary_missing_evidence`；
- `selected_parent_family_id`。

若现有 JSON 足以承载，不新增数据库列；若查询和审计频率证明必须结构化，再单独设计迁移，不在算法重构中临时扩表。

## 10. 代码改造范围

### 10.1 `app/chan_expansion.py`

- 抽取统一高级构造证明器。
- 将全局 `movement` 与局部笔流拆分转换为统一 `SegmentProof`。
- 统一校验方向、连续性、共同重叠、级别证明、确认状态和可用时间。
- 删除“调用来源不同导致判据不同”的分支。
- 保留扩展关系的独立接触证据计算，但不在该函数中直接生成父级几何。

### 10.2 `app/chan_structure.py`

- 在中枢延伸累计到九个原子单位时创建延伸升级候选。
- `_promote_expansions()` 改为扩展候选收集器与统一证明器调用方。
- 新增统一的父中枢提交、家族合并与修订逻辑。
- 延伸与扩展候选在提交前共同执行所有权冲突检查。
- 只有 `fixed` 且审计通过的父中枢/走势才能进入 `movement_units()` 和更高级递归。
- 保留 `U(1)=pen`、`U(L>1)=confirmed recursive movement` 的层级边界，禁止原始笔直接越级构造 L3 以上结构。

### 10.3 `app/rules.py` 与知识规则

- 提升定义版本，建议使用能明确表达本次语义的新版本，例如 `chan-period-unified-pen-promotion-v29`；最终名称在实现前确认。
- 明文写入“九笔触发检查，不保证升级”。
- 明文写入“延伸与扩展共享一个高级构造证明器”。
- 明文写入最低层笔代替次级别走势的工程简化及其递归边界。

### 10.4 持久化与展示

- 持久化候选来源、三段证明、动态/固定状态及缺失证据。
- 页面区分：延伸升级候选、扩展已成立但区间待定、动态高级中枢、固定高级中枢。
- 选中高级中枢时，高亮三段边界及其底层笔；不得只画高级矩形而隐藏构成依据。
- 对未升级的九笔以上结构显示具体缺失证据，而不是只显示“未升级”。

## 11. 审计不变量

结构审计至少新增或强化以下检查：

1. L1 中枢直接单位只能是确认笔。
2. L2 及以上中枢的三个段必须具有对应低一级证明。
3. 三段方向必须交替且 `S1 == S3`。
4. 三段必须连续，端点日期和价格满足统一容差。
5. 三段必须存在严格共同重叠。
6. 同一证明中单位不得重复。
7. 同级活动父结构不得重复拥有同一单位。
8. 进入单位不得补足九单位门槛。
9. 所有证明均不得引用未来证据。
10. `dynamic` 不得递归。
11. `fixed` 的确认时间不得早于任一必要证据。
12. 同一三段证明不得因候选来源不同生成两个父家族。
13. 扩展关系确认不得自动伪造高级区间。
14. 后续延伸不得改写固定核心。
15. 前缀重放与全量计算在同一观察时点必须同构。

## 12. 测试方案

### 12.1 单元测试

- 恰好九笔、合法 `3+3+3`、三段共同重叠，生成动态或固定 L2。
- 九笔但方向不交替，不升级并报告方向证据缺失。
- 九笔但仅相邻两段分别重叠、三段无共同重叠，不升级。
- 九笔含进入笔凑数，不升级。
- 九笔跨连续范围或数据缺口，不升级。
- 超过九笔时合法边界不是机械 `3/3/3`，能够找到最早合法划分。
- 多个合法划分按确定性规则选择同一结果。
- 第三段未完成生成 `dynamic`，确认后追加 `fixed` 修订。
- 动态结构不会成为更高级递归输入。
- 后续行情不改写历史核心与确认时间。

### 12.2 延伸与扩展一致性测试

使用完全相同的连续笔流，分别通过：

- 单中枢延伸候选；
- 两中枢扩展候选。

断言最终三段、`ZD/ZG`、形成时间、确认时间和父家族身份一致，仅 `formation_modes` 与来源证据不同。

再覆盖：扩展接触成立但三段证明不足，只保留 `confirmed expansion + unresolved boundary`，不生成伪高级中枢。

### 12.3 递归测试

- L1 使用笔作为直接单位。
- L2 使用由笔证明的 L1 走势段。
- L3 使用已确认、可递归的 L2 走势段，不直接消费原始笔。
- L2 动态结构不能被 L3 使用。
- 各级 `source_pen_ids` 可以完整追溯且无同级重复所有权。

### 12.4 前缀与时间测试

对同一行情逐笔追加重放，验证：

- 未到九笔时没有延伸升级候选；
- 第九笔确认后开始检查；
- 证据未齐时只报告候选与缺失项；
- 三段共同重叠首次可知时生成动态修订；
- 第三段边界确认时生成固定修订；
- 任一历史前缀结果不含未来 ID 或未来时间。

### 12.5 真实行情回归

冻结上证指数日线 `#12` 所需完整确认笔和前后上下文，至少覆盖 `2020-05-25` 至 `2021-07-09`。

验收输出必须逐笔列出：

- 笔 ID、方向、起止日期、区间和确认时间；
- 哪些笔属于进入、核心、延伸、外围、离开和回试；
- 所有候选三段划分及淘汰原因；
- 选中三段的共同重叠；
- L2 首次动态形成时间；
- L2 固定确认时间；
- 若最终仍不升级，必须给出可复核的具体缺失证据，不能只给结论。

同时加入至少三个反例：

- 九笔以上但三段无共同重叠；
- 两中枢扩展接触成立但高级边界不足；
- 看似延伸但中途已发生序列断裂或核心破坏。

## 15. 验收标准

以下条件必须全部满足：

1. 规则文档明确 `笔 = L0 次级别走势单位`。
2. 延伸和扩展共用同一个父级构造证明器。
3. 九笔达到后一定产生可审计检查结果，但不存在“九笔无条件升级”。
4. 同一笔流从延伸和扩展入口得到相同父级几何与确认时间。
5. 上证日线 `#12` 得到逐笔、逐段、带时间的确定结论。
6. 动态结构与固定结构区分清楚，动态结构不能递归。
7. 无重复单位所有权、循环证明、未来引用和历史核心改写。
8. 所有启用证券和周期重算成功，结构审计无错误。
9. 后端测试、前端测试、生产构建和 SQLite 完整性检查通过。
10. 页面实际显示与 API、数据库中的级别、范围和证据一致。

## 16. 风险与控制

- **候选组合爆炸**：按连续范围、最少三单位、已确认边界和最早可用时间提前剪枝；为单个范围设置可观测诊断，不静默截断。
- **历史结构大量变化**：新定义版本隔离运行，先输出新旧差异报告，再决定激活。
- **局部段与全局走势冲突**：使用统一段契约和选择顺序；冲突作为审计问题保留，不任意择一。
- **循环证明**：段的级别证据必须在父级证明前独立可用，父结构不能反向成为其组成段的证据。
- **动态结构污染递归**：以 `recursive_eligible=false` 做持久化和审计双重约束。
- **旧前端误读新状态**：API 保持旧字段兼容，同时新增显式状态；发布时前后端版本成对切换。
- **真实行情结论预设**：方案只要求 `#12` 必须进入统一检查，不预先硬编码其必然升级；最终结果由冻结笔流和统一证明决定。
