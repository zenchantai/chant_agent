# 自选股分类与分组迭代方案

## 总结

将现有单层自选列表升级为持久化分组树，支持一只股票加入多个自定义分组、分组独立排序、折叠展示，以及“全部 / 未分组”系统视图。保留现有行情同步、K 线切换和自选删除能力；标签、行业自动分类、动态排序和智能筛选不进入本次迭代。

`docs/plans/2026-09-13-watchlist-groups.md`

进入执行阶段后，第一步必须将本计划原文逐字保存到该路径并立即回读核验；若文件已存在，则使用 `2026-09-13-watchlist-groups-2.md` 等递增文件名。写入或核验失败时，不修改业务代码。

## 数据模型与迁移

- 保留现有 `stock_pool` 表和全局 `sort_order`，继续作为自选股票、后台同步和“全部”视图的权威来源，避免影响已有行情数据与同步任务。
- 新增 `watchlist_groups`：`id`、`name`、`sort_order`、`created_at`、`updated_at`。名称去除首尾空格后必须非空、最长 30 字符，并在忽略大小写后唯一。
- 新增 `watchlist_group_members`：`group_id`、`symbol`、`sort_order`、`created_at`，以 `(group_id, symbol)` 为唯一键，实现股票和分组的多对多关系。
- “全部”和“未分组”是系统计算视图，不写入分组表：“全部”来自全部启用的 `stock_pool`；“未分组”来自不存在任何有效分组关系的自选股票。
- 现有自选数据不做复制或重排；升级后自动出现在“全部”和“未分组”中。删除自定义分组只删除分组关系，不删除股票、行情、绘图或分析数据。
- 数据库初始化采用现有幂等建表模式；分组、成员关系、组内排序和级联清理均在事务内完成。

## API 与行为

新增聚合读取接口：

```text
GET /api/watchlist
```

返回：

```ts
type WatchlistResponse = {
  stocks: Stock[];
  groups: Array<{
    id: number;
    name: string;
    sort_order: number;
    member_count: number;
  }>;
  memberships: Array<{
    group_id: number;
    symbol: string;
    sort_order: number;
  }>;
};
```

分组管理接口：

```text
POST   /api/watchlist-groups
PATCH  /api/watchlist-groups/{group_id}
DELETE /api/watchlist-groups/{group_id}
PUT    /api/watchlist-groups/order
```

成员和组内排序接口：

```text
PUT    /api/watchlist-groups/{group_id}/members/{symbol}
DELETE /api/watchlist-groups/{group_id}/members/{symbol}
PUT    /api/watchlist-groups/{group_id}/members/order
```

- 创建、重命名和排序分组后返回最新分组数据；不存在的分组或股票返回 `404`，重名或排序集合不完整返回 `400`。
- 加入已有关系按幂等成功处理；新成员追加到该组末尾。
- 组内排序请求必须恰好包含该组当前全部成员，不允许重复、遗漏或夹带其他股票。
- 扩展 `POST /api/stock-pool`，增加可选 `group_id`。新增股票与分组关系在同一事务保存，提交后再启动原有全周期异步同步。
- 保持现有 `GET /api/stock-pool`、全局排序、删除和同步接口兼容，避免影响后台同步及已有调用方。
- 从搜索结果选择已在自选、但尚未加入当前自定义分组的股票时，只新增分组关系，不重复创建或触发行情全量同步。

## 左侧交互

- 左栏按顺序展示“全部”“未分组”和用户自定义分组；标题包含股票数量，所有分组均可独立折叠。
- 默认展开“全部”，其余分组默认折叠；折叠状态按稳定分组 ID 保存到 `localStorage`，刷新后恢复，已删除分组的旧状态自动忽略。
- 顶部保留添加股票按钮，并增加创建分组按钮；分组标题提供重命名、删除和拖拽排序入口，使用现有 Lucide 图标及工具提示。
- 从自定义分组标题打开股票搜索时，新股票自动加入该组；从左栏顶部或“全部”打开时，新股票进入“未分组”。
- 股票行提供“管理分组”菜单，以复选框一次维护多个分组；取消最后一个分组后，该股票自动出现在“未分组”。
- 自定义分组中的删除按钮仅执行“移出当前分组”；“全部”和“未分组”中的删除按钮执行“彻底移出自选”，沿用二次确认，并清理该股票全部分组关系。
- 每个自定义分组支持独立拖拽排序；“全部”继续使用现有全局排序；“未分组”沿用全局相对顺序。首期不支持跨分组拖拽，跨组归属通过“管理分组”菜单完成。
- 同一股票可以同时显示在多个已展开分组中；点击任意位置都切换到同一个股票和现有图表状态。
- 左栏继续使用自身滚动区域；桌面保持当前宽度，移动端沿用抽屉式侧栏，分组菜单不得造成横向溢出或遮挡股票操作。

## 默认约束

- 首期不预置“核心持仓”等业务分组，升级后的既有股票全部自然进入“未分组”，由用户自行创建分组。
- 不实现标签、嵌套分组、行业自动分类、动态行情排序、智能筛选和跨分组拖拽。
- 分组只影响左侧组织方式，不改变股票同步范围、行情缓存、缠论计算、绘图、分析记录和当前股票选择逻辑。
- 分组数据保存在 SQLite；只有纯界面折叠状态保存在浏览器本地。
