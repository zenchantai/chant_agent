# 多行情源择优与K线完整性修复计划

计划文档目标路径：`/Users/saber/Desktop/saber/投资/缠论/chant_agent/docs/plans/2026-09-24-multi-source-market-data-coverage.md`

## 摘要

把现有“BaoStock 有数据就直接采用、只有报错或空数据才切腾讯”的逻辑，改成通用的多源采集、质量比较、安全补洞和覆盖验证机制，适用于未来新增的所有自选证券，而不是 ETF 特例。

完成后：

- 只要 BaoStock、腾讯或已配置行情 API 中至少一个数据源拥有数据，系统就会选择时间跨度更长、有效K线更多、缺口更少的结果。
- 不再把“非空但被截断”的响应误认为完整数据。
- 多个来源能够安全衔接时自动补洞；复权价格冲突时不强行拼接。
- 如果所有来源都缺少某段数据，仍可能存在客观缺口，但系统必须明确标记 `partial`、展示缺口范围，不能静默显示成完整行情。

执行阶段第一步必须把本计划原文逐字保存并回读核验；如目标文件已存在，使用递增序号文件。

## 多源拉取与择优逻辑

- 新增统一的历史行情协调器，把已有缓存、配置的 `MARKET_DATA_API_URL`、BaoStock、腾讯都作为候选来源；所有来源先完整采集和验证，再决定写入，禁止边拉边覆盖正式缓存。
- 证券资料保留上市日期和证券类型：
  - 日线目标起点为上市日，结束于最近已完成交易日。
  - `5/15/30/60/120` 分钟线目标起点为所有候选来源中可证明的最早可用日，并验证此后每个交易日和盘中时间格。
  - `1` 分钟继续只保留最新交易日，这是既有产品定义，不宣称提供历史1分钟线。
- BaoStock 改为按自然年分段请求，避免一次长区间请求被 4,000、10,000、40,000 行上限静默截断；每段校验请求边界、首尾日期、重复行和交易日覆盖。
- 腾讯日/周/月/年继续分页获取完整历史；分钟接口作为最近数据候选，不能因只返回最近约320根而被误判为完整历史。
- 每个候选来源统一标准化为相同的 `period_key`、前复权口径、时间戳、OHLC、成交量和成交额，再进行：
  1. 非法价格、重复键、未来数据和盘中时间格检查。
  2. 上市日至最新收盘日或来源可用起点后的交易日覆盖检查。
  3. 连续区间、缺失区间、最新日期和有效K线数量统计。
  4. 来源响应是否触及请求边界的截断检查。
- 主来源按以下顺序确定：有效覆盖交易单元数量、缺口数量、最早起点、最新完成日期、异常数量；完全同分时按“配置行情 API、BaoStock、腾讯”的稳定顺序选择。
- 采用用户确认的“校验后补洞”：
  - 先选择综合覆盖最好的主来源。
  - 次来源只有在拼接边界附近至少5根已完成K线的 OHLC 一致时才允许补洞。
  - OHLC 一致标准为绝对误差不超过 `max(0.0001, 价格×0.000001)`；成交量和成交额差异记录为告警，但不单独阻止价格序列拼接。
  - 无重叠证据或价格口径冲突时不自动拼接，保留原有完整缓存并报告冲突。
- 已有数据库缓存也参与比较；新同步结果的覆盖范围不得比现有缓存更差。写入按“证券＋周期”事务提交，失败时保持原缓存和活动结构不变。
- `w/m/y` 同时比较三个候选：完整日线聚合、BaoStock直接周期、腾讯直接周期。
  - 完整日线聚合为优先来源，周期日期统一为该周期最后一个实际交易日。
  - 直接周期数据只有在与聚合结果重叠一致时才可补洞。
  - 已收口周期持久化并登记确认记录；当前周/月/年只作为 `provisional` 预览。
- 数据变化后，每个周期只执行一次结构重算；日线修订仅重建受影响的周、月、年逻辑周期。

## 覆盖状态与接口表现

- 新增持久化同步审计，记录每次同步的候选来源、请求范围、各来源起止日期和数量、截断/缺口、重叠差异、最终来源组合、覆盖状态及错误；用于重启后继续展示真实状态。
- 扩展现有覆盖接口，兼容保留原字段，并增加：
  - `target_start`、`target_end`
  - `selected_sources`
  - `candidate_summaries`
  - `uncovered_ranges`
  - `source_conflicts`
  - `coverage_reason`
- 自选股同步状态统一为：
  - `pending/running`：仍在采集和比较。
  - `success`：所有目标周期覆盖验证通过。
  - `partial_failed`：已有可用数据，但一个或多个周期仍存在来源无法补齐的缺口或冲突。
  - `failed`：没有取得可用数据，继续保留已有缓存。
- 新增自选仍立即成功并后台同步；多个来源无法补齐时按用户选择保留股票并明确告警，不阻止新增、不隐藏周期。
- “扫描并补齐缺口”改为针对具体缺口调用多源协调器，不再只是从缓存尾部向后增量抓取。
- 图表继续显示已有可用数据；覆盖告警展示具体缺口日期范围、采用来源和冲突原因，不能只显示笼统的“数据较少”。

## 测试与验收

- 单元测试覆盖：
  - BaoStock 非空但截断、分年后完整。
  - 腾讯分钟只返回最近窗口，不被误判为完整。
  - 日线从上市日开始验证。
  - 多源整源择优、安全补洞、无重叠拒绝拼接、复权价格冲突。
  - 缓存覆盖单调不退化。
  - 交易日缺失、单日分钟数量不足、停牌或来源无法证明状态。
  - 当前形成中K线不进入正式历史。
  - 周/月/年聚合、首个不完整上市周期、跨年 ISO 周和重复同步幂等。
  - 单一来源失败、全部来源失败及并发同步。
- 集成测试覆盖未来新增任意股票的完整流程：解析上市信息、多源分段采集、候选比较、事务写入、覆盖状态、结构计算和页面告警。

## 已确定边界

- 覆盖 `5/15/30/60/120/d/w/m/y`；`1` 分钟仍只保留最新交易日。
- 日线尽量追溯到上市日；分钟线从至少一个数据源可证明的最早可用日开始。
- 多源策略采用“主源择优＋重叠一致后补洞”，禁止无条件最大化拼接。
- 仅靠 BaoStock 和腾讯不能保证所有证券的全部分钟历史都存在；本计划保证的是自动择优、尽可能补全、永不静默丢失及不伪造完整性。
