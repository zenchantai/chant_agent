# 中枢 Z 段波动归属与证据驱动升级修复方案

## 一、目标与执行约定

修复当前 v25 将日线 L1 中枢普遍两两升级为 L2 的问题。保持“笔作为最低单位、非同级别分解、中枢族升级后显示活动修订”的模型，重点纠正波动归属、扩张证据和升级后的走势分类。

理论依据为 `../读缠论108课札记.pdf` 第 123—124 页；同步修订现有需求文档中“完整波动包络”的模糊表述，明确它与进入、连接路径的区别。

执行阶段第一步，将本计划全文保存至：

`docs/plans/2026-09-18-center-z-wave-expansion-fix.md`

文件重名时递增编号，立即回读核验后才修改业务代码。本轮规划阶段不写文件、不修改数据库。

已确定的规则：

- 保留原文的两个同级中枢扩张路径，不强制等待两个所属走势结束。
- 中枢核心与外围包络仅单点接触时保持候选，不生成零宽度高级中枢。
- 真正升级后保留家族身份，原低级修订作为证据；升级候选不能隐藏活动 L1。
- 验收依据是结构证据正确，不预设科创50或上证必须有几个 L1/L2。
- 保留当前未提交改动、标准笔算法、行情、自选、绘图、实时刷新和历史分页。

## 二、修复中枢状态机与升级算法

### 1. 统一价格范围和归属

中枢明确区分三种价格范围：

| 字段 | 计算来源 | 用途 |
|---|---|---|
| `ZD/ZG` | 初始三单位核心交集 | 固定中枢核心、延伸和回试判断 |
| `DD/GG` | 归属于本中枢、与核心形成方向一致的 Z 单位 | 同级新生、趋势与扩张判定 |
| `context_low/context_high` | 进入、连接、离开、回试等上下文 | 详情展示与诊断，不参与扩张判定 |

具体规则：

- Z 方向取核心第一、第三单位的方向，与 `entry_direction` 分开保存。
- 初始 Z 单位为核心第一、第三单位；后续只有已被状态机接纳的同方向延伸单位才能加入。
- `DD=min(Z.low)`、`GG=max(Z.high)`；进入段、最终离开段、相邻中枢连接段不得混入。
- 中间反向单位保留 `peripheral` 归属；它们不能单独扩大用于升级判定的 Z 包络。
- 临时离开后返回时，仅接纳符合延伸规则的 Z 单位；期间其它单位保留外围或上下文角色。
- 增加 `z_unit_ids`、`z_direction` 和端点证据。现有 `fluctuation_dd/gg` 统一为上述 `DD/GG` 口径，禁止再维护另一套混入进入段的升级包络。

高级标准递归的 Z 单位是合格低级走势。扩张生成的高级修订使用显式子中枢系统证据，不把底层笔伪装成高级走势单位。

### 2. 按时间顺序处理延伸、离开与新核心

替换当前向未来搜索一个新核心后直接跳过中间单位的处理方式：

- 每次只消费当前已经确认、连续且可用的低级单位。
- 初始核心形成后锁定 `ZD/ZG`，普通延伸不修改核心、不提高级别。
- 离开进入待判定缓冲区；独立新核心形成或有效破坏证据出现前返回，撤销离开候选。
- 边界接触单独记录，不能同时命中延伸和独立新生。
- 新核心必须有自己的非空合法进入段，不能复用旧核心或已锁定拥有单位。
- 行情缺口、序列边界、待定隔离区中断状态机；不能跨区组成中枢。
- 保存 `formed_at` 和输入确认时间，后续证据不能回填为更早的可用时间。

### 3. 固定关系判定顺序

同连续序列内两个相邻、合法、同级中枢，按以下互斥规则判断：

| 条件 | 结果 |
|---|---|
| 新核心与活动核心严格重叠，且尚未跨已提交边界 | 原中枢延伸，保留原固定核心 |
| 核心严格分离，后 `DD > 前GG + epsilon` | `newborn_up` |
| 核心严格分离，后 `GG < 前DD - epsilon` | `newborn_down` |
| 核心严格分离，Z 包络严格重叠 | 进入扩张证据校验 |
| 核心或 Z 包络仅边界接触 | `boundary_touch_candidate` |
| 连续性、归属或边界不合法 | `undetermined` 或 `sequence_boundary` |

`epsilon` 固定为 `1e-9`。判断使用原始数值，显示层四舍五入不参与计算。

### 4. 明确扩张完成证据

“包络重叠”不能独自触发升级。正式扩张必须同时具备：

- 两个不同的同级中枢，核心均由已确认单位形成。
- 两个核心严格分离；用于比较的 Z 单位归属正确。
- 子中枢拥有单位不重复，完整源区间连续。
- 两者之间具有可追溯的连接组件，不能跨缺口或隔离区。
- 至少一对分别属于两个中枢的已确认 Z 单位严格重叠；保存这对实际证据单位。
- 证据不要求改写已确认走势边界，也不切开任何核心。
- 全部证据在事件发生时已经可用。

任何条件缺失，输出带 `missing_evidence` 的扩张候选，保持两个低级中枢活动。`formed` 表示中枢已形成，本身不构成拒绝升级的理由；也不等于所属走势已经结束。

扩张的高级核心继续采用本项目明确的工程口径：

```text
parent.ZD = max(left.DD, right.DD)
parent.ZG = min(left.GG, right.GG)
```

只有正宽度交集才提交高级修订。该公式作为周期内简化模型的构造约定记录，不宣称仅由原文关系定理便唯一确定了高级走势的全部边界。

### 5. 升级、递归与修订一致性

- 正式升级沿用较早中枢的 `center_family_id`；以证据首次完整时间生成新修订。
- 两个子中枢的旧修订转为组成证据；候选升级不改变活动指针。
- 父结构保存两个子修订、连接组件、实际重叠单位、完整源笔和证据可用时间，不能遗漏连接区间。
- 同一事件有多个合法配对时，按最早证据可用时间、最早开始时间、稳定 ID 排序；已经参与该次升级的子修订不再重复参与并列升级。
- 后续中枢不能仅因与父包络重叠而被吸收。必须重新满足父级延伸规则，或与另一个完整同级结构形成独立升级证据。
- 标准递归仍只消费连续、已确认、分类明确且递归合格的低级走势，最高 L8。
- 扩张路径和递归路径具有相同级别、连续源区间及源单位集合时合并形成方式；核心结果冲突则输出问题，保留先提交的有效结构，不覆盖已确认历史。
- 已提交修订不可原地改写；追加行情可追加修订，但不能改变既有形成证据和已确认走势前缀。

## 三、联动走势、持久化、API 与前端

### 1. 走势和买卖点

- 所属中枢只是扩张候选时，走势维持原级别；只有正式高级中枢形成才更新未完成走势级别。
- 删除升级后无条件设置 `classification=consolidation` 的逻辑。
- 一个最高有效级别中枢可判盘整；多个同级完整中枢系统依次严格上移或下移才判趋势；关系混合则 `classification=null`、不可递归。
- 同一走势族在同一事件只生成一次修订，合并所有有效升级证据。
- 已确认低级走势保持原身份、边界和状态，可成为父级组成；历史修订引用不能冒充已完成子走势。
- 新关系结果重新驱动一类点的趋势资格、盘整背驰及三类点上下文。一类点不得来自虚假的同级趋势。
- 保持现有结构强度向量和 MACD 辅助判定公式；本次不另改力度标准。

### 2. 数据和审计

沿用现有 `chan_*` 表，修复证据和引用，不再次删除行情或重建八张保留表。

- 中枢单位关联表增加 `z_wave` 角色，`unit_kind` 写真实 `pen/movement/center_revision` 类型。
- 新增证据字段：`formed_at`、`promotion_confirmed_at`、`z_unit_ids`、`connection_component_ids`、`overlap_witness_unit_ids`、`missing_evidence`、`context_low/high`。
- 扩张候选存为有状态的关系记录；不伪装为正式活动父中枢。
- family 的当前修订按有效状态转换确定，不能简单选择最高 `level`。
- 发布新版本：
  ```text
  definition_version = chan-period-pen-recursive-non-same-level-v26
  center_envelope_mode = owned_z_units
  center_promotion_mode = verified_expansion_or_recursive_core
  envelope_touch_mode = candidate
  ```
- 更新计算器指纹及规则文档；v25 结果不得作为 v26 计算输入。

加强统一校验器，并取消扩张结构只检查“两子中枢”后跳过其余检查的分支。计算出口、入库前和独立审计均校验实际数值、单位类型、连续性、归属、连接、时间、父子关系和活动指针。

### 3. API 和显示

保持现有分组响应及 `/api/chart-data/{symbol}`：

- `structure.centers` 只返回有效活动修订；扩张候选通过 `structure.relations` 返回。
- `diagnostics=true` 返回历史修订及详细缺失证据。
- `structure_level=0` 继续提供全部活动层级；`1…8` 查询指定级别。
- 层级选项来自全量活动快照，分页不能改变层级、编号、状态或归属。
- 分页按引用闭包补齐子修订、Z 单位、连接组件和必要源单位。作为上下文返回的历史修订不自动绘制为活动中枢。
- 默认选中 L1；若 L1 为零，明确显示“当前无活动 L1，可查看 L2”，提供切换按钮，不静默回退。
- 扩张候选显示提示或虚线关系，保留 L1 矩形；正式升级后默认只画高级活动修订。
- 中枢详情显示固定核心、Z 包络、上下文范围、进入方向、Z 方向、升级时间和证据。
- 点击中枢分别突出进入、核心、Z 延伸、外围及连接组件；高级中枢支持展开子结构证据。
- 升级不导致买卖点日期或已确认走势端点随显示筛选改变。

## 四、测试与验收

### 1. 三组必须区分的确定性用例

在统一进入和核心规则下，采用以下价格序列：

| 用例 | 价格序列 | Z 包络与预期 |
|---|---|---|
| 同级新生 | `1,10,6,15,8,20,16,25,21,30,26,35` | `[6,15]`、`[16,30]` 严格分离；保留两个 L1，判向上新生 |
| 真实扩张 | `1,10,6,15,8,20,12,25,21,30,26,35` | `[6,15]`、`[12,30]` 重叠；完整证据通过后升级，父核心 `[12,15]` |
| 接触候选 | `1,10,6,15,8,20,15,25,21,30,26,35` | `[6,15]`、`[15,30]` 接触；保留 L1，不生成正式 L2 |

同时测试价格镜像后的向下用例。测试必须断言源单位、Z 方向、进入归属、核心和证据，不能只断言中枢数量。

### 2. 状态机和递归

- 进入段价格极端，但不改变 Z 包络及升级结果。
- 核心固定，延伸增加证据但不自动升级。
- 暂时离开后返回、首次完整回试、边界接触各走唯一分支。
- 有重叠但连接缺失、跨序列、输入未确认时保持候选。
- 中枢已形成、所属走势未结束，但扩张证据完整时允许升级。
- 第三个中枢不能仅凭传递重叠被吸收。
- L2/L3 标准递归不直接消费笔、不消费候选或待定走势。
- 多父中枢不能使走势被兜底判成盘整。
- 对每个输入前缀重算，验证中枢形成时间、升级证据时间和已确认走势前缀稳定。

### 3. 真实行情、接口和浏览器

- 固化科创50、上证日线的行情及标准笔夹具，逐对输出旧、新核心、Z 包络、关系和升级依据。
- 对每个发生变化的升级结果给出原因；不硬编码最终 L1/L2 数量或争议日期。
- 八张保留表在停服快照、候选数据库及切换前逐表核验行数和内容哈希。
- 验证错误证据不能激活运行，候选升级不能关闭低级活动修订。
- 验证两个标的 `5/30/d/w/m` 的版本、指纹、引用、分页和诊断响应。
- 浏览器实际检查 L1 默认选择、无 L1 提示、L2 切换、候选样式、角色高亮、历史拖动、普通绘图和自选行情。
- 执行后端 `pytest -q`、前端 `npm test -- --run`、`npm run build`、`git diff --check`、SQLite 完整性及外键检查。

任何关系不能从保存的源单位重新计算证明，均视为验收失败；“测试通过”不能替代真实行情的逐对证据检查。

## 五、执行顺序与发布

1. **保存计划与锁定口径**：全文落盘并核验，更新需求、规则和上述三组验收用例。
2. **先做失败测试**：证明现 v25 会把同级新生误判成扩张，并证明现审计无法拒绝不完整父级证据。
3. **修复计算与存储**：依次实现 Z 归属、时间顺序状态机、关系校验、升级修订、走势分类及引用校验。
4. **更新 API 与前端**：完成层级选择、候选展示、证据详情和分页上下文。
5. **离线重算验收**：在正式数据库的一致性副本上计算全部启用标的周期，生成逐对差异报告；阶段失败不改变线上活动运行。
6. **停服切换**：停止 `launchctl` 服务及同步，确认无 WAL 持有者；取得最新一致性备份并在 sidecar 数据库重算。全矩阵审计成功后关闭连接、完成 checkpoint，再原子替换数据库。
7. **恢复与实测**：恢复原常驻服务，检查健康版本、全部周期 API 和真实浏览器交互；失败回滚数据库及对应代码、前端版本。
8. **交付报告**：列明计划路径、实现结果、逐对升级证据、数据校验、测试与浏览器结果、未验证事项及计划差异。完整验收前保留回滚副本；通过后按明确路径清理临时副本。

本方案不以“让所有 L1 都重新显示”为目的：有完整升级证据的中枢继续显示高级活动修订，没有证据的保留 L1 或候选状态。
