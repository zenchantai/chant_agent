# 主图与副图可拖动布局改造

计划文档目标路径：`docs/plans/2026-09-13-chart-pane-resizable-layout.md`

## 总结

统一分时图与所有 K 线图的面板布局算法，消除主副图之间及副图之间的不合理空白。主图默认占可分配绘图区的 60%，副图均分剩余空间，并支持拖动每条水平分隔线调整相邻面板高度。

## 实现方案

- 执行阶段第一步将本计划原文写入目标文件并回读核验；若文件已存在，则使用 `-2` 等递增文件名。
- 用统一的像素布局计算器替换当前分时图、K 线图各自独立的百分比公式；布局输入包含图表总高度、顶部信息区、副图数量和面板比例，输出连续且无重叠的 ECharts `grid/xAxis/yAxis` 与分隔线位置。
- 默认比例为主图 60%，其余 40% 由副图平均分配；桌面端主图最小高度 `240px`、副图最小高度 `80px`，移动端分别为 `200px`、`72px`。副图较多且当前容器不足时自动增高整个图表，不再压缩到不可读。
- K 线顶部根据指标信息条预留空间，分时顶部避开设置按钮；只在最底部面板显示时间轴标签。K 线缩放条保留在底部，所有主副图的横轴统一参与缩放和十字光标联动。
- 在主图与第一个副图之间、每两个副图之间增加水平拖动条。拖动只改变相邻两个面板，总高度保持不变；达到最小高度后停止继续压缩。
- 拖动条使用 Pointer Events，支持鼠标和触摸；方向键按 `12px` 步进调整，双击恢复当前副图数量对应的默认布局，并提供 `separator` ARIA 语义和操作提示。
- 副图选择器位置直接使用统一布局结果，不再维护单独的 CSS 百分比公式，确保控件始终位于对应副图顶部。
- 按 `股票 + 周期 + 副图数量` 保存标准化面板比例，沿用 `localStorage`。切换股票、周期或副图数量时加载各自布局；缺失或损坏的数据回退到默认比例。
- 保留现有底部拖动条用于调整整个图表总高度；窗口变化或总高度变化时按保存比例重新计算各面板，不改变用户设置的相对高度。

## 接口与类型

- 新增内部 `ChartPaneLayout`/面板比例类型，以及纯函数：默认比例生成、比例校验、统一网格计算、相邻面板拖动调整。
- `ChartBuildContext` 接收当前面板比例和有效容器高度；不修改后端 API、行情数据结构或指标数据结构。
- 新增本地存储键：`chan-pane-layout-{symbol}-{timeframe}-{subplotCount}`，值包含版本号和标准化比例数组，便于后续兼容升级。

## 测试与验收

- 单元测试覆盖分时及 K 线的 `1～4` 个副图：网格连续、无大段空白、无重叠、轴与 series 索引正确、最小高度生效。
- 测试默认 `60/40` 分配、相邻拖动总高度守恒、上下限约束、双击恢复、损坏存储回退，以及股票/周期/副图数量之间互不串用。
- 前端执行 `npm test -- --run`、`npm run build` 和 `git diff --check`。
- 重启实际服务后，在桌面与移动视口分别检查分时、日线和 5 分钟图；验证拖动过程、刷新后恢复、切换周期恢复、缩放与十字光标同步，以及副图数量变化后的布局。
- 验收标准：分隔区域仅保留可操作的窄拖动条，不出现当前的大块空白；所有副图保持可读高度；拖动流畅且不影响画图、结构点击和图表缩放。
