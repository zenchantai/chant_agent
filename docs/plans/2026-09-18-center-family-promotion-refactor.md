# 中枢族升级吸收与走势级别同步重构

## Summary

将当前 v23 的“扩张时新增并列父中枢、随后另外生成父级走势”模型，重构为“同一中枢族升级、低级结构吸收为内部证据、所属走势同步升级”的正式模型。

核心语义：

```text
L1 中枢形成
→ 延伸时维持 L1 和固定核心
→ 连续同级中枢外围波动重叠形成升级候选
→ 扩张证据完成后，中枢族的活动级别升级为 L2
→ 原 L1 中枢转为该活动中枢的内部构成证据
→ 包含该活动中枢的正式走势按最高活动级别重新组织
→ 原 L1 走势转为内部子走势，不与 L2 走势并列显示
```

该模型仍是以当前周期确认笔为最低单位的周期内简化模型。日线 L1/L2/L3 仅表示日线数据域内部结构层级，不映射成真实分钟、周线或月线结构。

## Implementation Changes

### 1. 引入稳定中枢族与活动修订

- 每个中枢增加稳定的 `structure_family_id`，用于表达从 L1 到 L2/L3 的同一结构连续性。
- 每次形成、延伸或升级生成可审计的结构修订，至少包含：
  - `revision_id`
  - `structure_family_id`
  - `base_level`
  - `current_level`
  - `revision_kind`
  - `active`
  - `absorbed_by_center_id`
  - `absorbed_center_ids`
  - `previous_revision_id`
  - `upgraded_at`
- 普通延伸只更新同级活动修订的时间范围、拥有单位和外围波动，不改变 `current_level`，也不改变初始固定核心。
- 中枢扩张确认后生成同一中枢族的高级活动修订；不是向正式活动集合增加一个与原中枢并列、互不相关的父中枢。
- 被升级吸收的低级中枢保留为历史与内部构成证据，但标记 `active=false`、`display_status=absorbed`，默认正式 API 和图形不再将其作为并列中枢展示。
- 同一级别、同一源区间、同一升级证据只允许对应一个活动中枢族；追加数据时已确认前缀的族标识保持稳定。

### 2. 区分延伸、同级新生与升级吸收

- 延伸：后续单位与当前固定核心严格重叠并回到核心，继续属于同一中枢族，级别不变。
- 同级新生：两个同级中枢核心严格分离且外围波动包络也严格分离，保留两个独立活动中枢，可参与同级趋势。
- 升级吸收：两个连续同级中枢核心严格分离，但外围波动包络严格重叠，确认更高级别中枢族：
  ```text
  promoted.ZD = max(left.fluctuation_dd, right.fluctuation_dd)
  promoted.ZG = min(left.fluctuation_gg, right.fluctuation_gg)
  ```
- 升级后的时间范围、拥有单位、源笔、外围包络覆盖两个子中枢及其连接结构；方向取进入整个升级结构的低级走势方向。
- 低级固定核心不被改写；高级活动修订拥有自己的 `ZD/ZG`。这样用户看到的是同一结构升级，数据库仍可追溯升级前证据。
- 更高级别再次扩张时重复同一规则，允许同一族从 L1 升至 L2、L3，最高仍为 L8。

### 3. 重构正式中枢输出

- 结构计算内部保留所有修订和被吸收子中枢，供审计、证据检查和递归使用。
- 正式 `centers` 默认只输出每个中枢族的活动最高级修订，以及未被吸收的独立同级中枢。
- 增加 `center_revisions` 或等价内部集合，保存完整低级证据；被吸收中心不再混入前端正式编号。
- `center_relations` 使用 `absorbed_into`、`promoted_from`、`newborn_up/down`、`extension` 等关系明确表达升级，不再把扩张仅表示为普通 `parent_child` 并列关系。
- 中枢编号只对活动正式中枢排序；升级后保持中枢族身份稳定，显示级别和范围随活动修订更新。
- 审计要求：每个活动高级中枢必须能追溯到完整子中枢、连接单位、源笔和升级判据；被吸收低级中枢不得同时作为活动正式中枢出现。

### 4. 走势随中枢族同步升级

- 正式走势级别取其完整包含的最高活动中枢级别，不再保留一套并列 L1 走势和一套新生成的 L2 走势作为同层正式结果。
- 当 L1 中枢族升级为 L2 时，重新组织最后一个已锁定高级边界之后的后缀：
  - 覆盖升级中枢的最大合法区间成为 L2 走势候选；
  - 原 L1 走势作为 `child_movement_ids` 内部证据；
  - 被吸收 L1 走势标记 `active=false`、`display_status=absorbed`；
  - 图形和正式 API 只展示活动 L2 走势。
- 走势不能简单改标签：必须重新校验源单位连续性、中枢完整归属、买卖点方向交替和真实端点。
- 走势分类仍由活动同级中枢数量与关系决定：一个中枢为盘整，两个以上外围均严格分离的同级中枢为趋势；升级吸收结构不误判为低级趋势。
- 一个活动走势不得与其内部子走势同时消费正式展示层的同一源笔；内部证据允许引用，但必须通过 `active/display_status` 与正式结果隔离。

### 5. 买卖点按活动级别重新归属

- L1 买卖点在中枢升级后保留为内部证据，但不再切分顶层 L2 正式走势。
- 每个活动级别独立计算结构背驰、一二三类买卖点；只有与活动中枢同级的买卖点可以确定该级正式走势边界。
- 升级发生后，仅重算最后一个冻结高级边界之后的后缀；已确认且不受升级影响的历史前缀保持稳定。
- 买卖点增加或统一：
  - `structure_family_id`
  - `effective_level`
  - `active`
  - `display_status`
  - `absorbed_by_point_id`
- 被吸收低级买卖点仍可在证据检查器中查看，但默认不作为顶层图形标签显示。

### 6. API、持久化与前端

- 发布独立版本，例如：
  ```text
  definition_version = chan-period-center-family-promotion-v24
  hierarchy_version = center-hierarchy-v24-family-promotion
  expansion_mode = family_promotion_absorption
  movement_level_mode = highest_active_center
  ```
- 保留旧运行快照，不原地改写。新版本从现有完整行情重新计算并生成新活动快照。
- `/api/chart-data/{symbol}` 路径保持不变：
  - `centers` 返回活动正式中枢；
  - `movements` 返回活动正式走势及最右侧活动候选；
  - 证据上下文可附带被吸收修订，但不得混入正式编号；
  - 增加升级族、活动状态、修订来源和吸收关系字段。
- `/api/health` 返回新结构版本、`family_promotion_absorption` 扩张模式和 `highest_active_center` 走势级别模式。
- 前端默认只绘制活动最高级中枢和活动正式走势；级别筛选按活动级别工作。
- 选中高级中枢时，证据面板可展开其 L1 子中枢、低级走势和源笔；子结构使用弱化样式，仅在证据模式显示。
- 中枢升级后沿用中枢族显示身份，不在列表中保留一个同区间并列的旧 L1 正式项。

### 7. 数据迁移与运行策略

- 保留当前全部未提交 v23 改动，包括历史分页视野修复，不覆盖或回退。
- 不删除旧 `period_structure_runs` 和明细；新版本使用新指纹生成快照。
- 重算前停止服务与后台同步，备份 SQLite 主文件及 WAL/SHM，执行完整性和磁盘空间检查。
- 先 dry-run 计算和审计，再重算启用标的 `5/30/d/w/m`；全部通过后才切换活动快照。
- 失败周期不切换，禁止新旧规则结果混合返回。

## Test Plan

### 单元测试

- L1 延伸保持同一中枢族、级别和固定核心。
- 同级新生外围分离时保持两个独立活动中枢。
- 外围重叠时原 L1 中枢转为 absorbed，只保留一个活动 L2 中枢。
- L2 再扩张为 L3 时沿用稳定中枢族，不产生并列活动对象。
- 高级 `ZD/ZG` 使用升级关系重新计算，低级固定核心历史值不被覆盖。
- 被吸收子中枢、子走势和买卖点完整可追溯，但不进入正式活动集合。
- 活动中枢族与正式中枢一一对应；源笔和拥有单位无双重正式归属。
- 中枢升级后所属走势升级，原 L1 走势转为内部子走势。
- L1 买卖点不能切断活动 L2 走势；L2 边界必须由 L2 买卖点确定。
- 升级候选未确认时保持 L1 活动状态，不提前升级。
- 追加行情不改变已冻结且不受升级影响的正式前缀。

### 回归与真实行情

- 科创50日线验证升级区间只显示一个活动中枢，不再同时显示重叠 L1/L2 正式中枢。
- 科创50日线验证覆盖升级结构的走势只显示一个活动最高级走势，端点由同级结构买卖点确定。
- 上证指数日线验证此前重叠 L2 不再按父对象重复生成，升级后族身份、范围和证据一致。
- 输出每个升级案例的左右子中枢、外围区间、升级区间、活动修订、被吸收对象和所属走势证据。

## Assumptions

- “升级”是正式语义和用户展示语义；数据库仍保留升级前低级证据，不能物理删除或不可逆覆盖。
- 中枢延伸本身不升级；只有满足外围波动重叠的级别扩张条件才升级。
- 高级中枢拥有自己的核心区间，不能直接覆盖低级固定核心的历史值。
- 走势级别由其中最高活动中枢决定，但走势边界必须重新通过同级买卖点和完整归属校验，不能只修改 `level` 字段。
- 默认图形只显示活动正式结构；被吸收低级结构仅在证据模式展示。
- 本次继续采用当前周期笔作为最低结构单位，不恢复真实跨周期递归。
- 旧快照完整保留，新旧版本不混算；人工结构修订继续关闭。
