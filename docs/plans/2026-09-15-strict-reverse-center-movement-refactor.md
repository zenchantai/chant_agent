# 严格反向中枢确认的周期内走势重构

## Summary

将 `chant_agent` 重构为“每个行情周期独立计算、当前周期笔作为最低结构单位、反向独立中枢确认走势结束”的正式结构模型。

核心规则固定为：

```text
当前周期K线
→ 当前周期笔
→ 笔中枢 L1
→ 中枢关系
→ 当前周期走势
→ 反向独立中枢确认前一走势结束
→ 递归生成 L2/L3...
```

日线数据不足以还原真实5分钟、30分钟递归时，不伪造低级别结构；日线 `L1/L2/L3` 只表示日线数据域内部的结构层级，不映射成真实30分钟、周线或月线。

## Implementation Changes

- 保留 `P0 + P1/P2/P3` 方向性 L1 笔中枢入口，重构中枢到走势链路。
- 只有反向独立中枢才能确认前一走势结束；最新走势和没有反向确认的走势保持 `provisional`。
- 停用 `split_extensions=True` 将三笔分组直接确认为正式走势的语义；L2/L3 只消费低一级已确认正式走势。
- 统一 `status`、`confirmed_at`、`confirmation_center_id`、`termination_reason`、真实极值边界和候选尾部字段。
- 版本化结构算法和计算器指纹；保留旧快照，新算法从完整行情重算并激活新快照。
- 保持 `/api/chart-data/{symbol}` 路径；人工结构修订暂时关闭但保留历史记录。
- 更新前端状态展示、类型、详情和图层，不把周期内 L2/L3 显示成真实跨周期结构。
- 不覆盖当前工作区未提交改动。

## Test Plan

- 覆盖中枢严格重叠、延伸、暂时离开、同向分离、反向独立确认、右侧 provisional、真实极值回溯和连续区间边界。
- 覆盖 L2/L3 仅消费已确认低级走势、`2/3` 候选、`3/3` 确认及 extension/expansion 路径。
- 覆盖 API、数据库历史快照保留、版本失效、人工修订拒绝、前端测试、构建和浏览器交互。

## Assumptions

- 各行情周期独立递归；日线结构不等同真实30分钟或周线结构。
- 数据边界和行情缺口只能产生未完成状态，不能伪装为反向确认。
- 旧快照不做伪造状态转换，采用保留历史、生成新快照、切换活动快照的安全迁移。
- 计划文件写入并核验成功后才修改业务代码。
