# 严格反向中枢确认的周期内走势重构

## Summary

将 `chant_agent` 重构为“每个行情周期独立计算、当前周期笔作为最低结构单位、反向独立中枢确认走势结束”的正式结构模型。

核心规则固定为：

```text
当前周期K线
→ 当前周期笔
→ 笔中枢 L1
→ 中枢关系
→ 当前周期走势
→ 反向独立中枢确认前一走势结束
→ 递归生成 L2/L3...
```

日线数据不足以还原真实5分钟、30分钟递归时，不伪造低级别结构；日线 `L1/L2/L3` 只表示日线数据域内部的结构层级，不映射成真实30分钟、周线或月线。

## Implementation Changes

### 1. 重构正式结构状态模型

调整后端结构计算，使“走势形成”和“走势结束”分离：

- `formed`：已有一个有效中枢或有效低级组件，走势结构形成。
- `provisional`：走势已经形成，但尚未出现反向独立中枢。
- `confirmed`：已经由反向独立中枢确认结束。
- `unassigned`：首个有效中枢之前的笔或低级单位，不强行归入走势。

正式走势确认规则：

- 一个已确认中枢可以形成盘整走势候选。
- 两个或以上同方向、严格分离的中枢归入同一个趋势走势。
- 中枢延伸不生成新走势。
- 暂时离开原中枢、但尚未形成独立新中枢时，仍属于原走势/原中枢的未完成过程。
- 只有确认的反向独立中枢，才可以结束当前走势。
- 最右侧走势没有反向独立中枢时必须保持 `provisional`。
- 禁止使用“三笔分组完成”“达到九笔”“出现价格离开”直接确认走势结束。

### 2. 重写中枢到走势的构造链路

在 `app/hierarchy.py` 和 `app/period_structure.py` 中统一正式结构语义：

- 保留当前周期 `P0 + P1/P2/P3` 的方向性 L1 笔中枢入口规则。
- 保留 `ZD/ZG` 核心、`DD/GG` 包络、延伸、暂时离开和返回逻辑。
- 将低级单位先组织为中枢及其连接关系，再生成正式走势。
- 删除或停用 `split_extensions=True` 路径中“每组三个单位直接生成已确认走势”的语义。
- 不再将 `center_component_confirmed`、`extension_chunk_confirmed` 作为正式走势结束原因。
- 三笔组件可以作为内部候选或待确认组件，但不得进入正式 `confirmed movement` 集合。
- 同向新生中枢继续扩展当前走势；反向独立中枢生成前一走势的确认事件和下一走势的起点。
- 每个走势只消费同一 `continuous_range_id`、`sequence_id` 内连续且不重复的低级单位。
- 不跨越行情缺口、数据断点或序列边界。

### 3. 固定走势边界和确认字段

统一走势字段语义，至少保留：

```text
status
classification
direction
start_date
start_price
end_date
end_price
confirmed_at
confirmation_center_id
termination_reason
source_unit_ids
center_ids
child_movement_ids
boundary_source_unit_id
boundary_source_price
candidate_extreme_date
candidate_extreme_price
```

边界规则：

- `confirmed_at` 表示反向独立中枢完成确认的时间。
- `end_date/end_price` 表示走势方向上的真实极值边界，不简单等于最后一个中枢的终点。
- 上升走势回溯确认前的真实最高端点。
- 下降走势回溯确认前的真实最低端点。
- 同价极值选择时间更早的真实端点。
- 走势的起点和相邻走势只允许共享一个真实端点，不共享整段低级单位。
- 未确认走势保留当前可见尾部和候选极值，但不填充虚假的 `confirmed_at` 或 `confirmation_center_id`。

`termination_reason` 统一使用至少以下值：

```text
reverse_independent_center
sequence_boundary
data_boundary
provisional_tail
```

其中 `sequence_boundary` 和 `data_boundary` 只能表达结构流被截断，不能伪装成反向确认；只有 `reverse_independent_center` 才表示正式走势结束。

### 4. 重新定义 L2 以上递归

高级中枢继续采用周期内递归，但输入必须是低一级正式走势：

```text
L1 笔中枢
→ L1 正式走势
→ L2 中枢
→ L2 正式走势
→ L3 中枢
```

规则：

- 高级中枢只能消费低一级正式、连续、已确认的走势。
- 低一级走势未被反向独立中枢确认时，不得作为已完成父级构成单位。
- 两个合格低级走势可以保留 `2/3` 候选，但不生成确认父级中枢。
- 三个连续低级正式走势满足方向交替和严格重叠后，才确认父级中枢。
- `extension_3x3` 和 `expansion` 仍然可以作为父级中枢形成路径，但二者都必须使用已确认的低级走势。
- 高级中枢只新增父结构，不修改或删除原有 L1、低级走势和源笔。
- 递归上限仍为 `L8`，但实际可用级别由已确认低级走势数量决定。

### 5. 更新持久化、版本和 API

升级结构算法版本和计算器指纹，使旧活动快照不会继续被复用：

```text
definition_version
structure_version
calculator_fingerprint
```

数据库迁移采用安全迁移策略：

- 不删除旧 `period_structure_runs` 及其明细表。
- 旧活动快照保留为历史记录，不尝试伪造补充反向中枢证据。
- 新算法从现有完整行情重新计算支持的周期。
- 新结果创建新的运行快照并切换为活动快照。
- 旧结果不作为新走势确认输入。
- 对缺少完整行情的周期，只保留其可验证范围，不补造低级别数据。
- 迁移前生成数据库备份，并记录重算范围、成功数、失败数和版本指纹。

保持现有 `/api/chart-data/{symbol}` 路径不变，但返回新语义：

- `movements` 只返回正式层级走势。
- 正式 `confirmed` 走势必须有 `confirmation_center_id`，且该中枢必须真实存在并为反向独立中枢。
- 最右侧正式走势允许返回 `provisional`。
- 移除或废弃把 `hierarchy_component` 直接作为已结束走势的字段解释。
- 保留现有前端所需字段，新增或统一 `termination_reason`、`boundary_source_unit_id` 等字段。
- `/api/health` 返回新的结构版本和严格确认模式，例如：
  ```json
  {
    "structure_mode": "formal_hierarchy",
    "movement_confirmation_mode": "reverse_independent_center",
    "max_center_level": 3
  }
  ```

### 6. 前端展示调整

前端保持现有主接口和整体交互，不引入无关 UI 重构：

- 正式走势显示 `confirmed` 或 `provisional` 状态。
- `provisional` 走势使用明确的虚线、低透明度或状态标签。
- `confirmed` 走势显示其反向确认中枢引用。
- 走势详情展示：
  - 走势方向；
  - 盘整/趋势分类；
  - 起止边界；
  - 确认时间；
  - 结束原因；
  - 确认中枢；
  - 当前状态。
- 不把日线 `L2/L3` 的颜色映射误显示为真实周线/月线结构。
- 保留现有中枢级别筛选和结构点击能力。
- 对没有反向确认的最新走势，明确显示“未完成 / provisional”，不显示“已结束”。
- 前端不再根据数量把 `hierarchy_component` 直接称为正式走势。

### 7. 人工修订策略

本次重构期间暂时关闭人工结构修订能力：

- 禁止创建、更新、删除人工笔和人工 L1 中枢。
- 保留历史人工修订记录，不删除。
- 现有人工修订不参与新版本重算，避免旧语义污染严格确认结果。
- API 对结构修订请求返回明确的 `409` 或业务错误信息。
- 待严格走势确认模型稳定后，再单独设计人工输入层与自动派生层的合并规则。

## Test Plan

### 单元测试

新增或重写以下场景：

- 三笔严格重叠形成 L1 中枢。
- 单点接触不能形成中枢。
- 中枢延伸不生成新走势。
- 暂时离开后返回原中枢，不结束走势。
- 新中枢核心分离但未形成反向独立中枢时，原走势仍为 `provisional`。
- 同向严格分离中枢继续归入当前趋势走势。
- 反向独立中枢确认前一走势结束。
- 未出现反向中枢时，最新走势没有 `confirmed_at`。
- 走势结束边界回溯到真实最高/最低端点。
- 相邻走势只共享一个真实端点。
- 缺口、连续区间变化、序列变化不能伪造走势确认。
- 两个低级走势只生成 `2/3` 父级候选。
- 三个已确认低级走势才生成 `3/3` 父级中枢。
- 未确认低级走势不能参与 L2/L3。
- `extension_3x3` 和 `expansion` 的父级路径都必须引用已确认低级走势。
- 高级中枢新增后，低级中枢和低级走势仍完整保留。

### API、数据库和回归测试

- 验证所有正式 `confirmed movement` 都有有效反向确认中枢。

- 验证 `/api/chart-data/{symbol}` 对日线、周线和分钟周期的响应结构。
- 验证空数据、单中枢、只有候选走势和完整反向确认四种 API 响应。

### 验收标准

- 没有反向独立中枢的走势全部为 `provisional`。
- 所有正式 `confirmed` 走势均能追溯到反向独立确认中枢。
- L2/L3 不消费未完成走势。
- 日线结构不依赖不存在的5分钟、30分钟数据。
- 旧快照可审计，新快照可重算，活动数据版本一致。
- 后端测试、前端测试、构建、API检查和浏览器交互检查全部通过。
- 任何无法由当前数据确认的结构都明确保留为候选或未完成，不通过默认值强行确认。

## Assumptions

- 继续采用当前工程的方向性 L1 入口：`P0 + P1/P2/P3`；本次重点重构走势确认和高级递归，不把 L1 改为无方向的简单三笔扫描。
- 各行情周期独立计算；日线数据不被解释为真实低级别走势。
- 反向独立中枢是唯一正式走势结束确认条件；数据结束、行情缺口和序列边界只能产生未完成状态。
- 旧活动快照不做伪造式原地状态转换；采用“保留历史 + 新版本重算 + 新快照激活”的安全迁移。
- 保持现有 `/api/chart-data/{symbol}` 路径，避免无必要地引入 v2 接口迁移。
- 本次暂时关闭人工结构修订，不删除历史人工修订数据。
- 保留当前工作区所有未提交改动；只在已确认的结构计算、持久化、API、前端展示、规则文档和测试范围内修改。
- 计划文件写入并核验成功后，才开始任何业务代码修改。
